## 최소 신규 운영안 — R01-START-05/r1 후보

서버 제품 수정은 없다. 이미 검증한 같은 수정본을 **정지 상태에서 한 번 기동**하는 동작만 추가한다. Coordinator가 별도 변경 스레드의 Unity Coordinator 앱으로 필요한 사람 승인을 요청한다.

1. 별도 start-only 도구를 좁게 준비·독립 리뷰한다. 기존 전환 도구는 보존한다. 후보 경로는 `UnityClient/Builds/R01-Candidate/bin/MainServer.exe`, 위 SHA에 고정한다. cwd는 저장소 루트, 인자 없음, hidden 실행, 포트9999다. 기존 필수5 DLL hash와 실제 로드3종 경로 검사를 재사용하되 현재 원본 PID가 있다는 가정은 제거한다.
2. 실제 외부 조회 성공으로 게임 서버 프로세스/9999 listener·Established가 모두 없고 Unity Play/자동접속/runner가 정지했음을 확인한다. TEST* 환경변수 Process/User/Machine은 unset이어야 한다. DB/Redis/다른 서비스는 변경하지 않는다. 상태조회 실패는 비어 있음으로 취급하지 않는다.
3. 시작 시 로그가 truncate되므로 **기동 전에** 로그4종 및 모든 숫자 WAL의 실제 사본·hash를 보존한다. 사본 실패 또는 WAL nonempty면 중단한다. 기존 READ ONLY inspector SHA `170D9921CAE996F267F02BBCA4F441D8369CFBD339BD46A649A8B801A05D9C0D`로5011/5012를 보존 전후 두 번 관찰하고 행 값이 안정적인지 확인한다. 과거 q 저장 성공으로 해석하거나 값을 되돌리지 않는다.
4. 모든 guard 통과 후 후보를1회 시작하고 반환 즉시 native handle/PID/startticks를 고정한다. 30초 내 정확 PID/path/hash의9999 Listen·이번 stdout 준비 문구·필수 loaded DLL3종·신규 DB/WAL/오류 없음·무접속을 확인한다. 중복 spawn/네트워크 접속 probe는 하지 않는다.
5. 기동 결과 불명·조기 종료·준비 실패면 결과와 로그를 보존하고 **중단**한다. 자동 재시작, 자동 C0 복구, forcekill, 정상 q도 이 최소안에는 포함하지 않는다. 아직 살아 있는 후보라면 살아 있다는 상태와 PID를 그대로 보고하고 별도 운영 판단을 받는다. 실패를 숨기기 위해 프로세스를 정리하지 않는다.
6. 준비 성공 후 기수용 B05/V04 입력 배치를 진행한다. 첫 Full로 실제 HP/MP/좌표를 읽는다. 그 이후 실제 정상 퇴장→추가 접속 없이 저장 관찰→재접속 값을 비교한다. **사라진 기존 서버의 미저장 메모리는 회복/입증할 수 없다.** DB/HP 수정·스키마·계정·재시딩·WAL replay·원본 Game 변경은 제외한다.

이 안은 stop-only 경계 변경이 아니라 시작 조건 변경이다. 기존 정상 q에 따른 전용 상태 저장 승인은 사용할 q 대상이 없어 실행하지 않는다. 새 시작 역시 기존 서버 초기화/cache 흐름을 실행하므로 DB 전체 무변경을 약속하지 않으며, empty WAL guard는 nonempty 기록 재생 입력을 배제하는 좁은 조건이다.
