# Unity 맵과 서버 A* 연결 지점

## 마을과 부활 후보 — 2026-10-22

Zone 1은 몬스터를 생성하지 않는 마을이다. 보스도 제외하며 사냥은 Zone 2~6에 둔다. 사용자의 후속 AI/A*에서 몬스터 구역 이동을 추가하면 마을로의 진입을 별도로 금지해야 한다. 이번에는 AI·기존 Cell 이동 제한을 바꾸지 않았으므로 마을 침입을 막는 범용 AI 경계를 구현했다고 주장하지 않는다. 서버가 처리하는 명시적 사망 귀환 좌표는 전역 (10,10), HP/MP 최대 회복이며 EXP·재산은 보존한다. 초기 로그인 위치 보정은 HP0를 유지하는 기존 정책 그대로다.

## 현재 구현

AOI용 Zone/Cell을 유지하고, 충돌·길찾기용 1단위 격자를 별도로 추가했다. Unity의 고정 `C20FixedWorldMap` 아래 지면과 명시한 벽만 내보낸다. 풀·작은 장식과 구역을 따라 옮기는 기존 배경은 충돌 원본이 아니다. 높이축 없는 현 wire에 맞춘 단일 XZ 평면이며 경사·다층·NavMesh를 지원한다고 주장하지 않는다.

현재 후보의 코어 월드는 3열×2행의 600×400, 구역은 200×200이다. AOI Cell은 42단위·구역별 5×5를 유지한다. 전환 여유를 포함한 격자는 원점 (-5,-5), 610×410칸이고, 최댓값 (605,405)은 범위에 포함하지 않는다. 가장자리와 고정 벽 18개에 캐릭터 여유 폭을 적용한 결과 차단 칸은 2,900개다. Unity 자산과 C++ 비트맵의 250,100칸은 독립 리뷰에서 전부 일치했다. 실행 중인 서버에는 아직 반영하지 않았다.

사용자가 새 맵의 안전 지점 재배치를 선택했다. 로비에서 월드에 들어갈 때만 저장 위치가 해당 구역 밖이거나 막힌 칸이면 구역 원점+(10,10)으로 옮긴다. 이곳도 막혔으면 첫 AOI Cell의 통행 가능한 타일 중심을 순서대로 찾고, 없으면 입장을 거부한다. 정상 좌표·HP0·MP·캐릭터 ID·아이템·스킬 상태는 보존하며 NaN/무한 좌표는 재배치하지 않고 거부한다. 실제 구역 간 이동에는 재배치를 적용하지 않는다. DB를 직접 수정하거나 초기화하지 않았고, 새 위치는 기존 정상 상태 저장 경로를 따른다. ‘MMORPG 표준 크기’가 있다고 가정하지 않고 현재 6구역과 스폰 용량에 맞춘 크기다.

## 저작·내보내기

1. 고정 원점의 `C20MapAuthoring`에서 지면 BoxCollider와 충돌시킬 벽 BoxCollider를 명시한다. 장식 전체를 자동 수집하지 않는다.
2. `C02/World/Bake and Export Navigation`을 실행한다. 지면은 축 정렬 직사각형만 허용하고 회전·전단·누락·비정상 수치는 거부한다. 장애물은 보수적인 월드 AABB에 타일 반폭과 actorClearance를 적용한다.
3. `Content/C20WorldMap.asset`과 `CoreLib/Generated/WorldMap.inc`가 같은 통행 스냅샷을 담는다. 서버 출력은 임시 파일을 완전히 쓴 뒤 단일 atomic replace로 교체한다.
내보내기 도중 예외가 발생하면 직전 통행 배열과 기존 수정 상태를 복구한다. 성공 시에는 해당 맵 자산만 저장한다. 사용자 지면·장애물 편집을 취소하는 동작은 아니며, C++ 출력 후 자산 저장 실패나 프로세스 중단까지 두 파일의 원자성을 보장하지는 않는다.

4. 서버를 다시 빌드해야 적용된다. Scene 편집이나 export만으로 현재 서버가 바뀌지 않는다.

통행 자산의 전용 Inspector는 원시 배열 대신 저장된 격자와 통행/차단 합계를 표시한다. 큰 맵은 최대1024²로 보수적 축소하므로 한 픽셀의 빨강이 그 안의 모든 타일 차단을 뜻하지는 않는다. 원점·치수 변경은 기존 바이트의 해석도 바꾸므로 지면과 맞춘 뒤 다시 bake/export한다. Inspector는 Scene 변경을 자동 bake하거나 서버에 전달하지 않는다.

## A*가 사용할 계약

- 서버 `CoreLib/WorldMap.h`, namespace `Core::WorldMap`의 `OriginX/Y`, `TileSize`, `Width/Height`, `WalkableBits`를 사용한다. 배열은 y-major, bit=1이면 통행 가능이다.
- Unity X/Z는 서버 X/Y와 1:1이다. 셀 좌표는 `floor((world-origin)/TileSize)`, 노드 중심은 `origin+(index+0.5)*TileSize`이다.
- `IsWalkable(x,y)`는 노드의 통행 여부를, `CanTraverse(ax,ay,bx,by)`는 두 노드 사이의 실제 이동 가능 여부를 확인한다. A* 이웃 확장에도 후자를 적용해 대각 모서리 통과 규칙을 일치시킨다.
- CanTraverse는 선분이 지나가는 모든 격자를 검사한다. 선분이 격자선 위에 놓이거나 모서리에 닿으면 양옆 타일도 통행 가능해야 한다. 범위 밖·비유한 좌표는 차단한다.
- 현재 캐릭터 이동과 몬스터의 기존 이동 후보에 이 검사를 연결했다. A*·aggro 경로 탐색 자체는 사용자가 구현할 영역으로 남겼다.

## 경계 처리 판단

- 유지: 이웃 구역 전환은 같은 좌표가 양쪽의 겹침 영역 안에 있어야 한다. 행 끝 좌우 wrap과 존재하지 않는 위아래 구역은 거부한다. 현재 전환 계약에서 오류로 확인하지 않았다.
- 보완: Cell 개수의 절삭을 올림으로 바꾸고 마지막 Cell을 Zone 영역에 맞춰 자른다. 인덱스·Cell 용량이 감당하지 못하는 설정은 컴파일 단계에서 거부한다. 실제 2행과 달랐던 미사용 상수도 정정했다.
- 보완: 이동 예산으로 먼저 줄인 선분을 검사한 뒤 좌표를 반영한다. 정상 벽 충돌은 치트로 누적하지 않는다. 초기 입장은 유효 좌표 또는 위 안전 지점을 준비한 뒤 성공했을 때만 로비 소속을 제거한다. 구역 전환은 같은 좌표의 목적지 입장이 실패하면 원래 구역을 유지한다.
- 남은 구조적 제한: Zone 사이에는 AOI·스킬 판정을 공유하지 않는다. 겹치는 좌표라도 Zone 소유가 다르면 하나의 연속 전투 공간이 아니다. 이번 map export만으로 seamless 월드가 된 것은 아니다.
- A* 수정 시 주의: 현재 몬스터는 출생 Cell 안에서 이동하며 Cell 목록을 옮기지 않는다. 경로가 AOI Cell을 넘도록 바꾸면 monsterIndexes·cellX/Y·스냅샷/스킬 Cell 참조도 함께 갱신해야 한다. 이번에 이를 대신 구현하지 않았다.

## 이동·모션 변경

플레이어 예산은 4에서 6단위/초로 올리고 몬스터 속도 배율은 유지했다. 입력 목표를 서버의 이전 좌표에서 매번 새로 만드는 대신 누적하되 0.6단위 이내로 제한한다. 350ms 동안 서버 위치 진행이 없으면 화면을 서버 위치로 정리한다. ACK/sequence가 없으므로 완전한 입력 재연이나 모든 지연에서 6단위/초를 보장하지 않는다.

방향키의 대각 입력은 정규화하고 시각 모델은 이동 벡터를 따라 연속 회전한다. 스킬의 wire 방향 0..3은 유지한다. 실제 정적 파츠를 어깨·골반 pivot 아래 묶어 보행·공격 준비/휘두름·피격 반동을 표현한다. 서버 ActionResult·유효 HP 감소에서만 공격·피격을 시작하며 서버 actor root·카메라·HP바·범위선은 모션으로 움직이지 않는다. 신규 리깅·스킨 애니메이션 클립을 추가한 것은 아니다.

실제 조작·외관 확인은 사용자의 입력 보류 해제 뒤 한 번의 배치로 진행한다. 코드·빌드·분리 자동 검증과 실제 사냥 성공은 별도로 기록한다.
