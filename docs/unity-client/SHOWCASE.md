# AI-AGENT Unity 클라이언트 구현 작업

기존 MMORPG 서버와 직접 만든 2D 클라이언트에서 출발해, AI Agent를 활용해 3D 쿼터뷰 클라이언트를 구현한 기록입니다. 기능별 화면과 확인한 범위, 작업 중 바뀐 큰 기준을 모았습니다.

## AI Agent 워크플로우

사용자는 만들 기능과 우선순위를 정하고 결과를 판단합니다. 총괄 Agent가 목표를 정리한 뒤, 필요한 전문 역할을 골라 배정합니다. 모든 역할을 매번 실행하는 방식은 아닙니다.

### 에이전트 구성

- 사용자 — 목표·우선순위·화면 방향을 결정하고 결과를 검토
- 총괄 Agent — 작업 범위를 정리하고 필요한 역할을 배정하며 결과를 통합
- 기획 Agent — 플레이 흐름과 완료 조건을 정리
- 서버 분석 Agent — 서버 기능과 통신 규칙을 조사
- 구현 Agent — Unity 화면과 기존 서버 연결을 구현
- 아트 Agent — 캐릭터·배경·UI 표현을 개선
- 리뷰 Agent — 구현을 별도로 검토
- 테스트 Agent — 정해진 동작을 입력·응답으로 확인
- 기록 Agent — 확인된 기능과 화면을 공개 자료로 정리

## 하나의 기능이 만들어지는 흐름

기능 요청부터 구현·검토·확인을 거쳐 결과를 기록하는 순서입니다. 각 단계에 필요한 Agent만 참여합니다.

### 작업 흐름

- 목표와 완료 조건 — 사용자가 원하는 기능을 정하고, 총괄이 확인 기준을 구체화
- 필요한 역할 배정 — 기존 코드와 계약을 살펴보고 이번 기능에 필요한 담당만 선택
- 구현과 별도 검토 — 기존 구조에 기능을 연결하고 리뷰에서 변경을 다시 확인
- 필요한 범위 확인 — 변경된 동작을 중심으로 빌드·자동 검사·실제 입력 중 가능한 검증 수행
- 결과 정리 — 확인된 화면과 미해결 범위를 기록하고 다음 작업에 반영

### 피드백

- 리뷰·검증 피드백 — 문제의 재현 근거를 전달하고 구현을 수정
- 사용자 피드백 — 화면·조작 방향을 완료 조건에 반영하고 변경 범위를 확인

## Agent 활용 지표

새 Agent 실행은 에이전트를 새로 만들어 작업을 맡긴 횟수, 후속 작업 실행은 기존 에이전트에게 다시 작업을 맡겨 실행한 횟수입니다. 전체 실행은 두 횟수를 더한 값입니다.

기록 시작 이후 전체를 집계하며, 메시지·테스트 횟수나 토큰 사용량을 뜻하지 않습니다. 총괄이 직접 한 작업은 제외합니다.

## 지침 변경 이력

- 카툰풍에서 판타지 MMORPG 분위기로 — 캐릭터·필드·UI의 표현 방향을 바꿨습니다.
- 마우스 이동에서 키보드 조작으로 — 방향키 이동과 Z·X·C 스킬 입력을 중심으로 정했습니다.
- 텍스트 검증 화면에서 게임 UI로 — 아이템 그림, 상태 게이지, 스킬·채팅 표시를 실제 플레이 화면에 맞춰 개선하고 있습니다.
- 기사와 스킬 표현 보완 — 새 리깅 없이 기존 모델을 다듬고, 스킬마다 다른 동작·범위 표시를 적용하고 있습니다.
- Unity 맵을 서버와 공유 — Unity에서 편집한 통행·충돌 데이터를 서버가 함께 사용하도록 연결했습니다.
- 몬스터 AI와 화면 표현의 역할 분리 — 몬스터 AI는 사용자가 개선하고, Agent는 맵 공유와 클라이언트 표현을 담당합니다.
- 코드 구조 단순화 — 기존 책임과 상태 소유권을 확인하고 중복 코드·불필요한 계층을 줄이는 기준을 적용했습니다.
- 큰 기능 묶음으로 검증·전달 — 관련 화면과 연결을 모아 필요한 범위만 확인하고 검토 가능한 단위로 정리합니다.
- Agent 활용 기록 — 역할별 실제 실행·재활성화를 집계하고 확인할 수 없는 사용량은 비워 둡니다.

## 기존 Unity 구현

직접 구현한 기존 클라이언트는 2D입니다. 이동·몬스터·스킬·채팅·월드 진입이 들어 있었고, Unity 인벤토리와 거래소 화면은 없었습니다.
