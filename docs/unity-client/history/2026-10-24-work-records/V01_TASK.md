# V01 — 밝은 게임 화면 대표 샘플

사용자 지시: 디자인을 게임처럼 바꾸고 어두운 PPT 같은 화면에서 벗어난다. BRIEF의 밝은 스타일라이즈드 판타지·쿼터뷰·읽기 쉬운 캐릭터 실루엣을 기준으로 한 대표 화면만 제작한다. 첫 샘플을 보여준 뒤 대량 아트 제작 여부를 판단한다.

최신 사용자 방향: MMORPG 느낌. 웹 로그인 카드 느낌을 줄이고 큰 캐릭터, 금속/가죽 장비 실루엣, 문장·금속 장식 프레임과 깊이감 있는 밝은 판타지 전초기지/캐릭터 선택 화면을 우선한다. 서버에 없는 기능 버튼이나 가짜 수치를 MMO 관례로 추가하지 않는다.

실행 보류: 사용자가 다시 재개하라고 하기 전까지 Unity Play·실행 테스트·런타임 상태 변경 프리뷰·새 실행 캡처를 하지 않는다. 켜져 있던 Play는 종료한다. Edit-mode 에셋/Scene 저작과 컴파일·정적 참조 검토만 허용한다. 아래 실행 검증 계획은 재개 이후의 대기 작업이다.

포함: C02 로그인/실제 캐릭터 선택/필드 화면의 색·레이아웃·타이포·카메라·조명·1종 캐릭터 외형·장식 필드. 실제 서버 목록과 기존 버튼 동작을 유지한다. 필드의 주인공과 장면이 먼저 보이게 하고 상태/좌표는 보조 정보로 배치한다. 환경 장식은 시각 표현이며 새 충돌/맵 규칙/몬스터/게임 기능을 만들지 않는다.

제외: 신규 서버 기능·프로토콜·이동/전투 구현·가짜 HP/재화/목록·장식용 비활성 신규 기능 버튼·유료 에셋·대량 제작·C01 Scene 변경.

아트 담당 단독 소유: Assets/C02/Editor/C02SceneBuilder.cs의 시각 구성, Assets/C02/Art/ 새 아트/재질/meta, C02.unity와 관련 시각 material을 Editor API로 생성/저장. 기존 object 이름·C02WorldScreen 직렬화 참조와 실제 입력 경로는 유지한다. ClientCore/서버/런타임业务 로직·테스트·ProjectSettings/Packages는 수정하지 않는다. 필요 시 Coordinator에게 좁은 변경안을 제안한다.

Editor 조작권: 아트 담당 한 명. Play/테스트가 중지된 뒤 부여하며 반납 전 Coordinator나 다른 역할은 Editor/Assets를 수정하지 않는다. 서버 복구·권한 문서 확인은 독립적으로 Coordinator가 진행한다.

검증 목표/비용: 하나의 C02 대표 Scene을 컴파일·참조/가림 확인 후 실제 서버 로그인→목록 선택→필드 진입을 기존 입력 helper로 한 번 검증하고 1280x720 PNG를 확인한다. 상태를 만들어 넣은 미리보기는 서버 검증과 구분한다. 디자인 자체 확인 후 영향이 없는 전체 패킷 fixture는 반복하지 않는다. 실패나 수정이 있으면 해당 경로만 다시 검증한다. 첫 대표 샘플 제작·검증을 종료 조건으로 하며 사용자 확인 전 대량 확장하지 않는다.
