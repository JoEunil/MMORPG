# 첫 사냥의 성장·아이템 기획안 — 2026-10-28

**제안·미승인.** 사용자는 성장·아이템 기획을 먼저 선택했다. 아래 규칙·수치·서버 확장은 아직 확정하지 않았다. 이번 작업은 소스 읽기와 문서 작성이며 게임·DB·Unity·몬스터 AI·스폰 변경 및 실행 테스트는 없다.

## 현재 지원과 필요한 확장

기준은 Git 정본 `UnityClient/Builds/C10-Delivery/source`다. 최신 사용자 서버의 실행 상태와 동일하다는 뜻은 아니다. 정확한 경로·행은 [서버 지원 분석](history/2026-10-28-growth-items-planning/server-support.txt), 최초 상세 초안은 [기획 근거](history/2026-10-28-growth-items-planning/growth-plan-draft.md)에 보존한다.

## 추천: 첫 레벨업부터 완성

**마을→일반 몬스터 사냥→EXP 축적→첫 레벨업→성장 효과 확인→마을 복귀**를 첫 신규 구현 후보로 추천한다. 완료된 EXP 표시를 재확인하는 작업은 신규 성장 범위로 추천하지 않는다.

1. 기존 이동·Z/X/C로 사냥하고 처치 보상 EXP를 받는다. 새 임무 수락·보상 수령 버튼은 필요 없다.
2. 필요 EXP 경계를 넘으면 서버가 level과 성장 효과를 함께 갱신한다. 기존 Lv/EXP·HP/MP를 사용하고 응답 전에 수치를 올리지 않는다.
3. 같은 적과 다시 교전해 변화를 확인한다. 성장 효과는 **최대 HP 증가 한 가지**부터 비교한다. 새 스탯 배분·방어 공식·스킬 해금은 제외한다.

**미승인 조정 목표:** 초기 몇 레벨만 설계하고 첫 변화는 일반 몬스터 약 3~5회 처치 안에 경험하도록 비교한다. 현재 레벨 기준이나 측정 결과가 아니다. 원본 몬스터 HP1500/3000/10000만으로 처치 시간은 정할 수 없다. 실제 공격력·생존·소요를 보고 필요 EXP를 잡고 몬스터 AI와 기존 스킬을 몰래 조정하지 않는다.

**데이터 제안:** EXP는 총 누적값으로 유지하고 누적 임계값과 비교한다. 초기 목표 레벨과 운영 최대 레벨을 구분하며 전체 성장 곡선을 지금 만들지 않는다. 이미 높은 저장 레벨을 낮추거나 EXP를 초기화하지 않는다. 높은 기존 레벨과 EXP의 불일치, 한 번에 여러 경계 통과, 상한, 최대 HP 증가량·재접속 재계산, 레벨업 시 현재 HP 회복 여부는 구현 전 한 정책 묶음으로 정한다. 자동 전회복은 확정하지 않았다.

## 아이템은 회복 목적을 다음 후보로

추천 후속은 **일반 몬스터 처치→HP포션 가방 직접 지급→I에서 선택·사용→수량 감소와 HP 회복→다음 교전**이다. 현재 획득·사용은 없으며 서버 확장이다. 거래소 구매나 테스트 계정에 미리 넣은 물약은 신규 플레이어의 지속 공급원이 아니다.

기술 순서는 **레벨 전환→HP포션 사용 계약→처치 직접 지급 계약**이다. 사용만 구현한 단계는 완결된 아이템 경험으로 보고하지 않는다. 지급까지 연결한 뒤 MP포션을 같은 계약으로 다룰지 검토한다. 첫 레벨업과 포션 전체를 모두 첫 구현의 필수로 합치지 않는다.

희귀 확률 보상보다 짧은 사냥 안에 용도를 확인하는 확정 보상을 우선 비교한다. 어떤 처치에 몇 개를 주는지·회복량·재사용·전투 중 허용은 미정이다. 첫 보상 이력·처치 횟수 기능이 있다고 가정하지 않는다. 장비·바닥 줍기·새 재료·제작·상점·골드 드롭은 이 묶음에서 미룬다.

**회복 수요도 미평가다.** 기존 관찰 maxMP10000에 X/C 비용20이면 다른 비용·회복을 빼고 단순 계산상 약500회분이다. 현재 MP포션이 필요하거나 균형이 맞는다고 주장할 수 없다. 공급량·회복량·기본 능력치는 별도 조정 제안으로 다루며 저장 HP/MP 초기화나 스킬 하향으로 수요를 강제하지 않는다.

## 선택된 범위의 수용 조건

| 범위 | 정상 결과 | 실패·재접속 기준 |
| --- | --- | --- |
| 첫 레벨업 | 임계값 미만에는 변화 없고 경계 통과 시 level과 성장 효과 반영. 재접속 후 정합. | 중복 성장·클라이언트 선반영 금지. 사망과 겹칠 때 HP 정책과 저장 보장 범위 명시. 기존 높은 레벨/EXP 보존. |
| 회복 아이템 후보 | 처치 지급이 실제 가방에 반영되고 사용 성공 시 수량 감소·HP 회복을 함께 확정. | 가방 가득 참·수량 한도·HP가 가득 참/사망·연속 요청·끊김·저장 실패 정책 필요. 중복 지급/소비/회복과 가짜 성공 금지. 닫기는 사용이 아님. |

기존 막타 개인 보상을 유지하며 공동 분배를 확장하지 않는다. 다음 레벨 필요량은 확정 서버 기준과 연결할 때만 표시한다. 새 성장 창·포션 단축키는 기본 범위에 넣지 않는다. 구현 후 정상 경로와 가장 큰 실패 위험을 2~3개 시나리오로 확인한다. 이번 문서에서 레벨업·드롭·회복·균형은 미실행·미평가다.

## 의사결정 지원 담당에게 전달할 묶음

1. 첫 신규 묶음: **첫 레벨업(추천)** / HP포션 획득·사용. 둘 다 서버 확장이 필요하다.
2. 아이템의 첫 목적: **회복(추천)** / 장비 성능 / 기존 거래 대상으로 유지. 첫 묶음이 레벨업이면 후속 방향이며 즉시 구현 범위에 합치지 않는다.

수치마다 묻지 않고 선택 후 작은 조정안을 묶는다. 의사결정 지원 담당이 실제 답변을 적용 범위와 연결하고 Coordinator가 검수·통합한다. 현재 답변 수신·확정 기록은 없다.
