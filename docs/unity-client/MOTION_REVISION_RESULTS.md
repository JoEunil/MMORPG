# 방향키·보간·시각 예측 결과

## 구현한 범위

- codex/classic-mmorpg-motion에서 기존 클릭 이동을 카메라 기준 방향키 지속 입력으로 바꾸고 대각선 입력을 정규화했다. 스킬3슬롯을 Z/X/C로 연결했다. V, I가방/B거래소, 로그인 화면 분리는 후속 계획이며 이 묶음의 구현 완료로 표시하지 않는다.
- 자기 화면 위치를 별도로 유지한다. 명령은 여전히 서버 확정 좌표에서 최대1unit/50ms로 만들고 화면 예측은1unit 이내로 제한한다. 작은 패킷 보정은 화면을 즉시 덮지 않고, 입력 취소/불가 때 화면이 권위 좌표로 수렴한다. 큰 보정·HP0·Zone/연결 수명 전환은 초기화한다. 카메라는 화면 위치를 따른다.
- 다른 플레이어/몬스터는 서버 상태를 즉시 갱신하고 화면만 수신시각 기준4표본/75ms 지연 보간한다. 외삽은 하지 않는다. 최초 생성은즉시배치하고 기존 HP0제거·관측만료·type/Zone수명정리를 유지한다.
- wire에 ACK/sequence/tick이 없어 완전한 입력 재연/롤백·정확한 패킷 재정렬 검증은 제공하지 않는다. 서버 속도·맵·Cell·AI 변경은 다음 묶음이다. 여기서 수치 조정이 적용됐다고 주장하지 않는다.

## 리뷰와 실제 검증

독립 리뷰에서 자기 화면4unit/s와 서버 명령20unit/s 불일치, 취소 뒤 화면 오프셋 잔류, helper전용 테스트/별도어셈블리 접근 문제를 찾아 수정했다. Coordinator는 경계 이동 후보 실패 경로에도 화면 수렴을 적용했다. 최종 서버 원점·속도 예산·자기 예측 분리·원격 보간 검토를 마쳤다.

- Unity 컴파일 완료/errors0. 최초 자체 테스트 fixture의 미존재 Screen참조를 Coordinator가 고쳤다.
- 직접 영향 PlayMode 두 시나리오의 최종 결과 모두 통과. 첫 배치 자기상태/보정/초기화1통과, 원격1실패(int로uint사전키조회한 fixture오류). 기대 결과를 완화하지 않고 키타입만 수정해 원격1개만 재실행·통과했다. 이미 통과한 자기 시나리오는 반복하지 않았다. 원문 Captures/motion-revision-tests-first.txt와 motion-revision-remote-retest.txt, 시작 요약과 완료 결과를 구분한다.
- 자체 시나리오는 실제 C02 Full/Delta와 표시/취소 경로를 격리 fixture에서 호출한다. 실제 키보드·전송 주기·포커스 전환·실제 서버 연결을 검증한 것은 아니다. 원격은 실제 관측 객체 Full/Delta/프레임표시와 초기화를 확인했다. 이번 시나리오에서 몬스터 HP0실입력 처치는 실행하지 않았다.
- 실제 입력 배치는 미실행. 실제 서비스 포트9999/3000/3306/6379는 정상 수신 읽기로 확인했고 서비스 변경/재시작0. 화면 점검에서 다른 게임 창이 겹쳐 있는 것을 보고 창 활성화·키/마우스 입력을 보내지 않았다. 사용자의 입력 테스트 재개 권한 자체를 철회한 것으로 해석하지 않고 환경이 비었을 때 한 번 실행할 항목으로 남긴다.
- 자동 승인 검토는 컴파일 상태 조회와 무조건 테스트 시작을 묶은 실행을 거절했다. 컴파일 완료·failed=false·errors=[]를 독립 조회한 뒤 같은 선택 테스트가 정상 승인돼 실행됐다. 정책 약화/다른 경로 우회/중복 사용자 승인 없음.
