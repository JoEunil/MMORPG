# AI 에이전트로 만드는 Unity MMORPG

기존 게임 서버의 기능을 Unity 쿼터뷰 MMORPG 화면으로 옮기며, AI 에이전트 협업이 실제 구현·리뷰·플레이 검증에 얼마나 쓸 수 있는지 살펴보는 프로젝트입니다.

**현재 상태:** C08 구역 이동과 C09 거래소 조회의 로컬 구현·리뷰·실행 검증을 마쳤습니다. 두 변경은 [PR 29](https://github.com/JoEunil/MMORPG/pull/29)로 제출됐으며, 2026년 10월 19일 기준 병합 전입니다.

## 왜 시작했나

서버 개발에서 제한적으로 사용하던 AI를 게임 클라이언트 개발 전반에 적용해 보려 합니다. 기능 범위와 게임 방향은 사람이 정하고, 에이전트가 기획 조사부터 구현, 아트, 코드 리뷰, 실제 실행 확인과 기록까지 맡습니다. 결과는 설명이나 코드 생성만으로 판단하지 않고 Unity 화면과 서버가 돌려준 상태로 확인합니다.

## 에이전트가 협업하는 방식

Coordinator가 작업 범위와 순서를 정하고, 필요한 역할에만 일을 나눕니다. 같은 Unity Editor나 파일을 동시에 건드리지 않으며, 기능 구현이 끝나면 독립 리뷰와 작업 묶음 검증을 거칩니다.

- **총괄(Coordinator):** 작업 범위와 인계를 관리하고 결과를 확인합니다.
- **기획 담당:** 플레이 흐름과 사용자가 확인할 완료 조건을 정리합니다.
- **서버 분석 담당:** 실제 서버 처리와 패킷 계약을 확인합니다.
- **구현 담당:** 기존 계약에 맞춰 ClientCore와 Unity 화면을 연결합니다.
- **아트 담당:** 쿼터뷰 필드와 캐릭터·장비·UI의 시각 방향을 다듬습니다.
- **코드 리뷰 담당:** 변경을 구현자와 별도로 검토합니다.
- **테스트 담당:** 실제 입력, 서버 결과, 화면 표시와 캡처를 확인합니다.
- **문서 담당:** 검증 근거와 공개 설명을 정리합니다.

일반적인 흐름은 다음과 같습니다. 서버에 없는 기능은 MMO 관례만으로 만들어 넣지 않습니다.

1. 서버 기능 조사
2. 작업 범위 확정
3. 구현과 아트
4. 독립 코드 리뷰
5. 묶음 실행 검증
6. 결과와 사이트 갱신

## 서버 기능을 Unity 화면으로

클라이언트는 기존 서버에 로그인하고 캐릭터를 선택해 월드에 진입합니다. 필드에서는 서버의 위치·상태를 기준으로 캐릭터와 전투 화면을 갱신하고, 구역 이동은 서버의 이동 확인과 새 상태를 받은 다음 조작을 이어갑니다. 거래소 화면도 서버 응답을 그대로 보여주며, 조회 결과가 없을 때 임의의 매물이나 수치를 채우지 않습니다.

현재 작업에서 확인한 기능은 로그인·캐릭터 목록·월드 진입, 필드 이동과 구역 전환, 플레이어·몬스터 표시, 전투와 HP 0 처리, 채팅·인벤토리 연동, 거래소 매물 조회입니다. 기능마다 검증 범위는 다르며, 아래 C08·C09는 각 작업의 실제 검증 결과를 설명합니다.

### 거래소 조회

![실제 서버가 반환한 무기·방패 매물 목록](media/bazaar.png)

C09 최종 입력 검증의 실제 Unity 화면입니다. 유형 2 조회에서 반환된 12개 매물이 UI에 표시됐습니다. 검증한 제품 파일을 해시 대조해 기록한 전달 커밋은 `c33ba6b`입니다 — [PR 29](https://github.com/JoEunil/MMORPG/pull/29).

같은 C09 입력 검증에서 빈 결과와 페이지 전환·새로고침·창 닫기 및 다시 열기를 확인한 화면입니다. 빈 서버 응답은 빈 상태 그대로 표시합니다.

## 검증 결과와 현재 범위

C08에서는 구역 이동의 서버 회귀 39/39, 영향받은 Unity 회귀 6/6, TCP 경계 회귀 3/3을 확인했습니다. 실제 마우스 입력으로 Zone 1→2→1을 이동하고 정상 종료했습니다. 초기 Unity 회귀와 첫 TCP 수신 실패는 보존한 뒤 원인을 수정하고 영향 범위만 다시 검증했습니다. 각 숫자는 서로 다른 검증 묶음이며 전체 테스트를 한 번에 재실행한 수치로 합치지 않았습니다. [C08 변경](https://github.com/JoEunil/MMORPG/commit/68233678dac27a1fd69b987a8d327075ff8f65ed)

C09에서는 Unity 회귀 83/83, TCP 영향 회귀 4/4를 확인했습니다. PR28 수정 통합 회귀는 기존 52개와 추가 1개를 별도로 확인했습니다. 실제 화면에서 거래소 유형·페이지 조회, 새로고침, 닫기와 다시 열기를 수행했고 7개 서버 응답이 화면과 일치했습니다. DB 매물 수는 조회 전후 같았으며, 이 작업은 읽기 전용 조회입니다. [C09 변경](https://github.com/JoEunil/MMORPG/commit/c33ba6bbe415c3a0c96de6d15a92b1ffcfb66031)

거래소 **등록·구매·취소·수령은 아직 클라이언트에 연결되지 않았고 검증 범위에도 포함되지 않았습니다.** C09는 기존 매물 조회만 다룹니다. 2026년 10월 19일 이 설명을 정리한 시점에 PR 29는 검토 중입니다. 이후 기능이 바뀌면 실제 검증과 병합 상태를 확인해 이 페이지도 갱신합니다.

## 다음에 이어갈 일

다음 작은 작업은 현재 로그인한 캐릭터의 ‘내 매물 조회’입니다. 기존 서버 계약 조사를 마쳤으며 아직 구현·실행 검증 전입니다. 등록·구매·취소·수령은 기존 영속화·소유권·중복 처리까지 확인한 뒤 별도 작업으로 연결합니다. 쓰기 기능을 검증할 때는 전용 테스트 계정의 아이템과 재화가 실제 서버 결과에 맞게 반영되는지 확인해야 합니다.
