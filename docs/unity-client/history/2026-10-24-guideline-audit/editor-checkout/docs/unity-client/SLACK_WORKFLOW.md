## 현재 운영 규칙

승인된 목표 안의 일반 단계와 작업 단위는 완료 후 자동으로 이어간다. Coordinator는 완료 요약을 게시한 뒤 전체 계획에서 다음 미완료 작업을 즉시 시작한다. Slack 답장, `계속`, `재개`, 다음 단계 승인을 기다리지 않는다. 사용자 결정이나 사전 승인이 필요한 작업은 그 부분만 대기시키고 독립 작업은 계속한다. 기존 전용 로컬 테스트 환경의 서버 시작·정상 종료·정상 재시작과 같은 후보 빌드 교체에는 사람 승인이나 Slack 재개 명령을 요구하지 않는다. 강제 종료, DB 초기화·파괴적 변경, 운영 환경 확대는 사전 승인을 유지한다.

중요한 코드베이스 변경 승인은 구현·독립 리뷰·배치 테스트·복구 준비가 끝난 PR 생성 직전에 한 번만 요청한다. 계획 단계나 테스트 전에는 승인 요청을 올리지 않는다. 승인 대기 중에는 PR 생성·push·병합·공개만 멈추고 필요한 수정·재검증은 계속한다.

사용자에게 보이는 Slack 본문은 쉬운 말로 `한 일 → 막힌 점과 해결(있을 때만) → 최종 테스트 결과 → 다음 작업`만 3~5줄로 적는다. 서버 코드를 바꿨으면 바뀐 동작과 실제 적용 여부를 한 문장으로 알린다. 요청 ID·경로·hash·PID·명령·나열식 로그는 상세 문서로 옮긴다. 승인 요청은 변경 효과·주요 위험·검증 결과를 짧게 적고, 회신 문구는 모바일에서 전체 복사하기 쉬운 `승인 <짧은 ID>` 한 줄로 제한한다.
