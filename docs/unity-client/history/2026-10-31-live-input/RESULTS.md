## 관측 한계와 근거

- Editor callback의 키보드 열은 실제 사용자 조작 중에도 모두0이었다. 직접 키 눌림 시간의 근거로 사용하지 않는다. 게임의 이동 의도·서버/렌더 좌표·창 상태와 사용자 완료 회신을 구분해 기록했다. 자동화 키 전송 실패를 게임 키보드 결함으로 판정하지 않았다.
- [내 캐릭터 분석](analysis-player.json)은 서버(px,py)와 화면(vx,vy)을 비교한다. 몬스터 열(sx,sy/mx,my)을 내 캐릭터 분석에 사용하지 않는다. 정지 분석은 다음 이동 의도가 시작되면 끝낸다.
- [몬스터 분석](analysis-automation.json), 원본 표본 [자동 관측](automation-motion.csv.gz)·[직접 입력 관측](manual-motion.csv.gz), [실제 GameView 캡처](live-input-result.png)를 보존했다. 이전 Editor 예시는 실제 게임 캡처로 바꿔 부르지 않는다.
- 확대 시야의 AOI 경계 정합성·고지연 네트워크·구역 왕복·사용자 최신 서버 리팩터링과의 조합은 이번 배치에서 검증하지 않았다. 기존 통과한 자동 테스트는 반복하지 않았다.

## 종료와 다음 상태

실제 Disconnect 후 Play를 종료했다. 이번에 시작한 MainServer와 로그인 호스트만 고유 stop-file로 정상 종료했다. 신원 확인 과정의 경로 구분자·UTC 변환 문제는 확인식을 바로잡아 해결했으며 다른 프로세스나 강제 종료를 사용하지 않았다. 기존 MySQL84·Redis는 계속 Running이다. 포션1개 소비와 캐릭터 이동은 정상 게임 동작이며 DB 재시딩·초기화를 하지 않았다.
