# C07 — 인벤토리 조회

목표: 실제 접속 캐릭터의 서버 인벤토리를 가방 패널에서 슬롯·아이템 ID·수량으로 조회한다. 빈 목록, 실패, 접속 종료와 늦은 응답을 구분한다. 장착·소비·드래그 이동·거래·재시딩은 제외한다.

기준: BRIEF 인벤토리 조회, C07_CONTRACT.md의 실제 wire/실행 경로. 시작 HEAD 7c83226. 기존 PR27은 그대로 두며 이번 변경의 push/PR 갱신은 최종 승인을 기다린다.

소유: 계약 분석 c07_contract(C07_CONTRACT.md), UI c07_ui(C07InventoryScreen/Setup 및 meta), 코어·통합·문서·Editor root. 테스트 중 Assets/Packages/ProjectSettings 쓰기를 멈춘다. 기존 정책 문서와 원본 Game 변경은 보존한다.

완료 조건: 요청 opcode20과 응답21 실제 계약 일치; count만큼 유효 행만 snapshot으로 표시; 요청 중 중복 없음; 실패·종료 후 이전 데이터 노출 없음; 실제 UI 클릭에서 서버 응답/표시/지면 입력 차단/캡처 확인; 독립 리뷰 후 관련 회귀 한 배치 통과. 현재 서버의 세션 캐릭터 연결 누락 의심은 분석 후 최소 로컬 후보로 보완한다. DB 데이터 직접 쓰기·초기화는 하지 않는다.

검증 계획: 구현·독립 리뷰를 끝낸 고정 버전에서 파서/수명/서버 후보 회귀 및 기존 관련 회귀 각 1회, 실제 로그인→가방 열기→조회→닫기·다시 열기/새로고침→정상 종료를 하나의 입력 배치로 수행한다. 전용 계정만 사용한다. 빈 실데이터는 빈 목록 성공으로 기록하고, 비어 있지 않은 목록은 결정적 fixture로 별도 검증하여 실서버 비어 있지 않은 결과로 오인하지 않는다. 요청 응답 제한 10초, 진입 120초, 전체 입력 180초 이내 종료. 실패는 보존하고 원인 보완 후 영향 범위만 재검증한다. 기능 테스트는 저작 중 실행하지 않는다.

권한: 승인된 목표 내 최소 후보 구현·리뷰·로컬 테스트와 정상 테스트 서버 전환을 진행한다. 최종 diff/검증/복구 준비 후 PR 직전에 Unity Coordinator 앱으로 승인 요청한다. 강제 종료·DB 삭제/재시딩·운영 조작·외부 게시는 제외한다.

준비에서 확인: Inspect-C07Inventory.cjs의 READ ONLY 조회로 캐릭터5011/5012 모두 inventory 행 누락을 확인했다. 실서버 성공 목록/빈 목록은 이 데이터에서 검증할 수 없다. 실제 입력 배치에서는 status0 실패 응답·명시적 재조회·정상 종료를 검증하고, 성공/빈/최대10행의 표시·수명·파서는 결정적 fixture로 구분해 확인한다. DB 행을 만들거나 실패를 빈 가방 성공으로 바꾸지 않는다. 초기 Unity 회귀 코드의 누락된 ClientCore.Services using 1개를 컴파일 단계에서 보완했다(기능 테스트 실행 전).
