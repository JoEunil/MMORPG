# Unity 클라이언트 현재 기획 기준

실행·승인은 [AGENTS.md](../../AGENTS.md), 현재 완료/미완료는 [HANDOFF](HANDOFF.md), 작업 순서는 [개편 계획](MMORPG_REVISION_PLAN.md)을 따른다. 이 문서는 기획 범위이며 실행 완료 증명이 아니다.

## 목적과 범위

기존 서버 기능을 보여주는 3D 쿼터뷰 정통 판타지 클라이언트다. 로그인 → 캐릭터 선택 → 필드 → 이동/전투/기존 보상 → 채팅·가방·거래소·구역 이동을 실제 서버 지원 범위 안에서 연결한다.

길드·공성전·펫·퀘스트·파티·강화·자동사냥 등 미확인 시스템과 더미 버튼/예비 모델/후속 구현 목록을 일반 MMO 관례로 추가하지 않는다. 기존 거래·인증·DB 규칙은 UI 개선으로 바꾸지 않는다.

Unity 기준은 현재 프로젝트 6000.0.47f1이다. 변경이 필요하면 이유·호환 영향을 제시한다. 카메라는 기본 고정이며 서버(x,y)를 Unity(x,z)에 대응한다. 실제 좌표·방향 계약은 소스를 확인한다.

## 조작·화면·기획 품질

- 방향키 홀드 이동/해제 정지, 기존 3슬롯 Z/X/C. V는 미배정. 마우스는 UI·대상 선택에 사용한다. 채팅·모달 입력 중 이동/스킬을 막는다.
- 대각선 이동과 서버 스킬 4방향을 구분하고 서버 이동 예산·충돌·소유권을 따른다.
- HP/MP는 오른쪽 하단의 간결한 게이지, 스킬은 채팅과 게이지 사이 중앙. I가방/B거래소, 아이템 그림·수량·가격·재화 UI를 사용한다. 필요한 상단 정보 텍스트는 유지한다.
- 입장·캐릭터·필드·몬스터·스킬은 같은 정통 판타지 방향으로 맞춘다. 신규 리깅은 제외한다.
- 형태/비례 → 실루엣/색 → 재질/텍스처 → 조명/공간감 → 모션/VFX → 세부 묘사 순으로 대표 화면을 비교한다. 지나치게 단순한 기존 결과를 그대로 대량 복제하지 않는다.
- 공격·피격·사망 모션과 반투명 범위·차징은 실제 phase/범위에 맞춘다. 서버가 제공하지 않은 정확한 피해 수치를 만들지 않는다.
- 실제 플레이 카메라에서 적/플레이어/예고 구분·UI 겹침·재질 일관성을 확인한다. 성능은 목표 기기·해상도를 정한 뒤 측정하고 미측정 FPS를 성과로 쓰지 않는다.

새로운 기획·아트 방향은 [선택지 비교 절차](WORKFLOW.md#기획아트-방향-선택)로 정한다. 선택한 요소·피할 요소·사용자가 밝힌 이유·적용 범위·임시/확정 상태를 위의 관련 기준에 갱신한다. 아래의 기술 계약과 기존 확정 조작을 취향 선택만으로 바꾸지 않는다.

## 계약의 확인 지점

로그인/진입은 Login·NonZoneHandler·ViewModel, 이동/스킬은 ZoneState_Actions·PacketTypes·SkillData, Full/Delta/ActionResult는 ZoneState_Snapshots를 확인한다. Full 하나를 전 세계 목록이라고 가정하지 않는다. 이름은 현재 PROFILE_BATCH 계약을 따른다.

인벤토리는 실제 슬롯/수량 조회를 기준으로 하며 enum이나 DB만으로 장착·소비·드래그 영속화를 가정하지 않는다. 거래소는 현재 외부 패킷→세션/캐릭터→캐시 처리 경로를 확인한다. 등록 골드 수수료·구매 다이아 차감·대금 다이아 수령·Outbox와 지급 완료를 구분한다.

맵은 C20/C24 exporter와 CoreLib/WorldMap.h·Generated/WorldMap.inc를 기준으로 하며 과거 Zone100/Cell22/4구역 값을 현재 규격으로 재사용하지 않는다. 현재 생성 데이터·Config·서버 실행 값을 대조한다. AOI Cell/통행 격자/Zone 소유권은 별개다. Zone1은 몬스터 없는 마을, 명시적 HP0 귀환과 로그인 HP0 보존은 구분한다.

몬스터 AI는 사용자 소유다. A* 없음·Cell간 이동 허용·Wandering의 이동/대기·이동 후 phase 위치를 존중하며 대신 개편하지 않는다.

## 데이터 저작과 내보내기

Unity 저작 에셋/명시한 맵 데이터 → 검증 → 결정적 서버 후보 출력 → 기존 ID/참조/용량/경계 확인 → 서버 정적 데이터 소비·빌드 순으로 진행한다. Mesh·재질·Prefab·Scene·NavMesh 바이너리를 서버 데이터로 혼동하지 않는다. 범용 데이터 플랫폼·핫리로드·새 DB 테이블은 만들지 않는다.

- 기존 skill/monster/item ID와 배열 참조를 보존한다. Unity GUID/instanceID를 서버 ID로 쓰지 않는다.
- 좌표축·원점·단위·겹침·경계·모서리·방향, 실제 50ms 정수 tick과 변환/반올림을 확인한다.
- phase/step 개수·필요한 거듭제곱 조건·스폰/고정 용량·유한값·수치 범위를 검증한다.
- 같은 입력의 출력 순서·결과를 유지하며 난수 스폰의 영역/분포를 이유 없이 고정 좌표로 바꾸지 않는다.
- 연결된 생성 파일은 함께 검증·교체하고 실패 시 이전 유효 후보를 보존한다.
- 후보 버전/해시는 내부 근거에 남긴다. 새 버전 교환 프로토콜을 가정하지 않는다. Editor 수치 변경을 실행 서버 적용으로 보고하지 않는다.

초기 범위·수치·S01/S02/S04 계획 원문은 [이력](history/2026-10-24-guideline-audit/README.md)에 보존했다.

## 기획·아트 일괄 선택 — 2026-10-25

사용자가 개별 작업마다 피드백하는 방식 대신 여러 샘플을 한 번에 보고 고른 뒤 함께 제작하도록 지시했다. 기사 현재 형상·기존 전투 표현 방향은 선택 완료로 유지한다. 다음 비교 묶음은 마을 입구/필드 장식, 가방 정보 배치, 거래소 판매 흐름의 각2안이며 현재는 시안 준비만 승인된 상태다. 실제 선택 전 해당 제품 화면·맵을 대량 변경하지 않는다. 서버 미지원 장착/소모/NPC 서비스·몬스터 AI·경제/수치·충돌 변경을 포함하지 않는다. 샘플은 로컬 HTML/SVG 배치 시안으로 실제 Unity 구현이나 실행 검증과 구분한다. 선택 후 기존 기준의 작은 보완은 자율 처리하고 통합 결과로 피드백받는다.

### 일괄 선택 확정 — 2026-10-25

사용자가 마을A(성곽길 정돈), 가방A(그리드+오른쪽 상세), 거래소B의 간소화를 선택했다. 거래소는 기존 계약에 따라 판매 등록 확인에는 골드 수수료, 구매 확인에는 차감할 다이아를 명확히 표시한다. 판매 가격의 다이아 단위는 유지하되 등록할 때 다이아를 차감하는 기능으로 바꾸지 않는다. 불필요한 등록 후 잔액 예측·긴 설명을 덜고 아이템/수량/가격 확인과 명시적 최종 실행은 보존한다. 선택 이유는 사용자가 별도로 밝히지 않았으므로 추측하지 않는다. 이 세 작업은 함께 구현·통합 확인하고 각 작업마다 추가 취향 확인을 요구하지 않는다.

### 다음 레벨 디자인 — 마을에서 첫 사냥까지

**기획 초안:** 기존 전역 좌표·6구역 구조로 짧고 읽기 쉬운 한 방향의 시작 동선을 만든다. 경로 기준점은 `마을 스폰 (10,10) → 현 포장길 끝 (100,10) → Zone 2 진입 (205,10) → 기존 일반 몬스터 구역 (Cell x=279..321, y=-5..37)`, 복귀는 같은 길을 역방향으로 이동한다. Zone 2 남쪽 진입 행에서 첫 두 42단위 스폰 Cell은 비어 있고 세 번째 Cell에는 일반 몬스터 2마리가 배치된다. Cell 안의 스폰 위치는 런타임에 선택되므로 정확한 만남 좌표나 안전을 보장하지 않는다. 마을 Zone 1은 몬스터 0마리이며 현재 사망 귀환 (10,10)은 유지한다. 별도의 귀환 버튼이나 새 서버 기능은 계획에 넣지 않는다.

현재 생성된 실제 통행 그리드로 `CanTraverse((10,10),(100,10))`, `CanTraverse((100,10),(205,10))`, 전체 `CanTraverse((10,10),(205,10))`가 모두 가능하다. y=5..15의 약 10단위 폭도 x=10..205 전 구간이 통행 가능해 직선 동선용 장애물 우회는 필요하지 않다. 이 검토는 생성된 통행 데이터의 오프라인 판정이지 플레이 화면이나 실입력 검증은 아니다. 기존 성곽길 포장은 x≈7..100에서 끝났으며 이번에는 기존 메시 두 개를 재사용해 x100..205 구간을 같은 길 축으로 연결했다. 실제 통행 데이터와 장애물에 대한 사전 검사 및 에디터 배치 확인을 마쳤고, 2026-10-25 실제 서버 세션의 합성 방향키 입력으로 연장 구간을 왕복하고 Zone1→2→1 및 정지 위치 유지를 확인했다. 물리 키를 누른 왕복 검증은 아니다. 장식 배치만으로 서버 충돌이나 안전 지대를 뜻한다고 표현하지 않는다.

현재 확정 범위에서는 첫 사냥의 스폰 수·종류, 몬스터 AI·A*·Cell 이동·phase, 전역 맵 크기, 충돌 원본과 서버 계약을 바꾸지 않는다. 레벨 연출은 기존 빈 진입 구간과 기존 일반 몬스터 배치, 길의 시각적 연결을 활용한다. 실제 카메라 가독성은 화면 확인 후 판단한다. 이후 플레이 결과가 서버 수치나 통행 충돌 변경을 요구하면 영향과 대안을 모아 별도로 검토한다. 미지원 퀘스트·NPC·레벨/아이템 보상이나 가짜 표시를 설계하지 않는다.

길 확인 중 확장 전 V04MeanderingMeadow의 북/동 원경이 실제 통행 구간을 가리는 것을 재현했다. DistantForestRidge0/1만 비활성화하고 남/서 원경과 기존 오브젝트는 보존했다. 충돌·스폰·통행 데이터 변경은 없다.

## 선택 대기와 전달
