# AI-AGENT Unity 클라이언트 구현 작업 — 공개 기준

## 목적

이 사이트는 기존 MMORPG 서버와 직접 만든 2D 클라이언트를 바탕으로 AI Agent와 진행한 3D Unity 클라이언트 구현 결과와 경험을 보여준다. 방문자가 실제 화면을 먼저 보고, 기존 기반·사람의 판단·Agent가 맡은 작업을 구분해 이해할 수 있게 한다. 서버 프로젝트 소개나 설계 설명은 원문 링크로 연결한다.

## 콘텐츠와 탐색

- 결과 화면과 구현 기능을 중심에 둔다. 대표 이미지, 기능별 상세, 이전 화면은 해당 결과를 이해하는 데 도움이 되는 만큼 제공한다.
- 홈·기능 상세·작업 과정·경험 회고는 각 목적에 맞게 나눌 수 있다. Markdown의 제목·분량을 화면 구조로 그대로 옮길 필요는 없다.
- 기존 2D 구현과 Agent가 진행한 3D 구현을 구분한다. 기존 2D에는 이동·몬스터·스킬·채팅·월드 진입이 있었고 인벤토리와 거래소 화면은 없었다.
- 이미지·GIF는 실제 게임, 선택용 시안, 에디터 예시, 자동 fixture 중 무엇인지 밝힌다. 선택 시안은 구현 결과로 표현하지 않는다.
- 기능 페이지에는 조작과 관찰한 결과, 확인 범위를 짧게 설명하고 필요할 때 화면 이력과 상세 근거로 연결한다. 거래소 기능은 한 묶음, 인벤토리 기능은 한 묶음으로 탐색할 수 있게 한다.
- 내부 작업 ID·승인 번호·PID·해시·원문 로그·테스트 개수는 공개 설명에 나열하지 않는다. 사람이 이해하는 기능 이름과 짧은 검증 요약을 사용한다.

## AI Agent 활용 경험

사람이 정한 목표와 판단, Agent에 맡긴 작업, 결과를 검토하고 수정한 사례를 실제 기록에 근거해 설명한다. 원하는 조건을 구체적으로 전달해야 했던 점, 게임의 조작감은 자동 검증만으로 충분하지 않았던 점, 기획·아트 예시를 비교해 선택하는 방식으로 바꾼 점을 구분해 다룰 수 있다.

문제·선택·조정·결과를 간결하게 연결하되 모든 기능에 동일한 사례 구조를 강제하지 않는다. 추정한 만족도·생산성·비용 절감은 쓰지 않는다. 공식 대안 탐색 방식과 과거 실행을 구분하며, Tree of Thought 같은 정식 기법이 적용됐다고 확인되지 않았다면 주장하지 않는다.

## 사실과 기록

- 확인된 사용자 의견과 실제 코드·화면·검증 근거를 구분한다. 계획은 완료로, 자동 테스트는 실입력으로, 준비된 시안은 제품 화면으로 바꾸어 표현하지 않는다.
- 실패·제약·미확인 사항은 이해에 필요한 범위에서 짧게 표시한다. 사용자 경험이나 결과를 빈칸 없이 채우려고 추측하지 않는다.
- Agent 지표는 요청된 집계의 기준과 범위를 설명하고 실제 활성화 기록을 사용한다. 테스트 횟수, 메시지 수, 토큰·비용과 혼동하지 않는다.
- 공개 결과에 변화가 생겼을 때 관련 원본과 화면을 갱신한다. 과거 화면은 비교에 필요한 기록으로 보존한다.

## 원본 관리

홈 콘텐츠는 `SHOWCASE.md`, 기능별 상세는 `portfolio/*.md`, 작업 경험은 `EXPERIENCE.md`, Agent 활성화 지표는 `AGENT_USAGE.md`를 원본으로 사용한다. 웹 페이지는 이 원본에서 생성하며, 지침이나 과거 기록을 공개 소개의 근거 링크로 추가하지 않는다. AI-AGENT.md는 공개 결과와 프로젝트를 안내한다.

배포 전에는 대표 화면의 출처와 링크, 기능 간 탐색, 화면 크기별 가독성을 확인한다. 변경이 없는 기능의 게임 검증을 사이트 갱신만을 위해 반복하지 않는다.
