# AI-AGENT Unity 클라이언트 구현 작업 — 공개 기준

## 목적과 화면

포트폴리오 제출 시 별도로 전달할 AI Agent 기반 Unity 구현 결과와 경험을 보여준다. 사이트 이름은 'AI-AGENT Unity 클라이언트 구현 작업'이다. 기존 서버 포트폴리오/PPT는 링크로 연결하고 설명을 복제하지 않는다.

방문자가 실제 결과, 사람/Agent 역할, AI 활용의 이점·남은 문제, 소스/문서 링크를 찾을 수 있어야 한다. 근거 없는 사용자 만족·학습·생산성을 만들지 않는다.

- 홈 상단에서 Agent 구성과 사용자 판단 → 총괄 배정 → 구현/독립 리뷰 → 검증 흐름을 읽기 쉬운 도식으로 설명한다. 일반 팀 프로젝트처럼 쓰지 않는다.
- 대표 화면·작업 목록에서 상세·화면 이력으로 탐색한다. 거래소 조회/판매/내 매물은 거래소 하나, 인벤토리는 인벤토리 하나로 묶는다.
- 작업 제목과 이미지 모두 해당 상세로 연결하고 큰 캡처는 원본을 열 수 있게 한다.
- 작은 장식 소제목·작은 링크·PPT식 반복 패널·부자연스러운 구호를 피한다. 글자·도식·캡션을 실제 크기에서 읽히게 한다.
- 한 페이지에 모두 담지 않고 Markdown 순서·분량을 화면에 그대로 옮기지 않는다. 대표 화면/갤러리 한 구간을 브라우저에서 확인한 뒤 확장한다.

## 기존 구현과 기능 설명

사용자의 기존 2D Unity는 이동·몬스터·스킬·채팅·월드 진입을 구현했고 인벤토리·거래소는 구현하지 않았다. 서버 기능 존재와 Unity 화면 구현을 혼동하지 않는다. 기존 화면은 출처가 확인된 자료를 상단 기존 구현 영역에 보여준다.

'기존 시연 자료' 반복 링크·긴 면책 설명을 붙이지 않고 로그인·사냥처럼 기존 기능을 새 기능으로 소개하지 않는다.

상세는 '구현한 기능 / 현재 확인한 범위 / 화면 기록'을 기본으로 조작과 결과를 짧게 쓴다. '해결한 문제'·'에이전트를 활용한 과정'을 모든 페이지에 반복하지 않는다. 실제 사례가 있을 때만 사람의 목표·판단, Agent 수행, 검토·수정을 근거로 설명한다. 평가하지 않은 경험은 생략한다.

진행 흐름·지침 변경 이력에는 큰 결정만 자연어로 요약하고 내부 단계표·개별 버그·미세 수정·PR/승인/병합 상태를 공개 목차나 본문에 나열하지 않는다.

## 화면 이력과 사실성

기능이 바뀌면 같은 상세의 현재 설명·대표 화면을 갱신하고 과거 캡처·촬영일을 보존한다. 캡션에는 조작과 결과를 짧게 쓴다.

실제 게임·자동 fixture·에디터 예시·콘셉트·중간 결과를 구분한다. 예시값/촬영용 조명을 밝히고 실거래/실입력 성공으로 표시하지 않는다. 실패를 지워 성공처럼 꾸미지 않는다.

C09/R01·승인·PID·해시·원문 로그·테스트 개수는 내부에 두고 필요한 상세 근거만 링크한다. 공개 Agent 활성화는 사용자 요청 지표이며 테스트 횟수와 구분한다.

## 지표와 원본

기획 Agent·서버 분석 Agent·구현 Agent·아트 Agent·리뷰 Agent·테스트 Agent·기록 Agent 이름을 워크플로우와 동일하게 사용한다. AGENT_USAGE의 기록 시작 이후 전체 신규·재활성화·역할 합계를 대조한다. 미확인 귀속·토큰·비용을 추정하지 않고 총괄 직접 작업·메시지·테스트 횟수를 활성화로 세지 않는다.

홈 SHOWCASE.md, 상세 portfolio/*.md, 지표 AGENT_USAGE.md가 각각 정본이다. build.py로 HTML을 만들며 담당·전달 절차는 DELIVERY.md를 따른다.

데스크톱/모바일에서 필요한 화면의 이미지·GIF 재생·가독성·도식·링크·탐색을 확인한다. 시각 변화가 없으면 이유만 기록하고 새 캡처를 의무 생성하지 않는다.
