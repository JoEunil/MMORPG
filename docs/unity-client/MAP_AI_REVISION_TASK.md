# 다음 작업: 맵·몬스터 AI

상태: 실제 서버/클라이언트 계약 읽기 완료, 제품 변경·시험은 아직 없다. 사용자 허용 범위는 맵 확대·Cell·자연스러운 몬스터 배치/움직임을 위한 서버 변경이다.

## 확인한 사실

- 현재 Zone100 + 양쪽버퍼5 = 110×110 보행 영역, Cell22로5×5. AOI는 현재/주변3×3셀, activeZone4. 클라이언트 C02의 bounds와Zone1↔2 연결도100/5 상수를 반복한다.
- 화면 지면은 대략[-70,170]의240×240이며 서버가 허용하는[-5,105] 밖의 배경은 걸을 수 없다. 장식 지면만 늘리면 맵 확대가 아니다.
- 현재 셀별 일반8+강한2, 중앙보스1 = Zone당241. Cell당균일난수·중앙예외이므로 자연스러운 사냥터 분포를 별도로 설계할 필요가 있다.
- 배회는0.6unit/tick(50ms)=12unit/s의한축왕복, 추적은유형별1/1.2/.6unit/tick=20/24/12unit/s. Cell경계를넘으면어그로를끊고다른Cell로재등록하지않는다.
- aggroTick은초기화/리셋만보이고증가경로가없어timeout과보스거리공격조건이도달하지않는것으로분석됐다. 구현 전관련경로를다시대조해수정하며100tick은50ms기준5초이므로주석10초와혼동하지않는다.

## 구현 순서·완료 조건

1. 먼저 기존 Cell 안의 AI와 속도를 별도 후보로 고친다. 일정한 셀 왕복 대신 개체별 짧은 배회/정지·방향변경과 고향 영역을 사용하고, 추적/어그로해제 카운터를 실제50ms와 일치시킨다. 임의로 새 공격/충돌/보상을 추가하지 않는다. 이동·공격 목표 수치는 플레이 조작과 함께 정한다.
2. 맵 확대 후보에서 Zone 폭/버퍼/Cell 개수를 함께 정의한다. 초기 검토 후보는 Zone200·버퍼10·Cell22(총220/22=10셀)처럼 정수 분할이 되는 구성이다. 이는 아직 적용값이나 성능 합격값이 아니다. 적 총수는 면적에 따라 자동4배 복제하지 않고 사냥 구역별 밀도/휴식 동선으로 정한다.
3. 서버Cell/AOI/스폰·클라이언트bounds/Zone연결·export검증/Inspector·보행영역/시각 경계를 같은 기하 후보로 갱신한다. spawn center와 per-cell총수/고정용량도맞춘다. 서버지원없이Cell사이를추적하는것처럼표시하지않는다. 그런추적을넓히려면셀등록/AOI갱신까지같이검증한다.
4. 최소 검증은 속도/영역·AItimeout 핵심 자동2~3개, 실제 사냥 이동1배치다. 의미 없는 부하 수치/전체회귀/DB리시딩은 넣지 않는다. 실행이 필요한 순간에만 정상 재시작한다.
