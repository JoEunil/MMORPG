# 거래소 판매대금 수령 연결

사용자가 2026-10-20 일반 개발을 재개했다. PR37은 병합 확인했으며 origin/master 0f9b96d 기준 codex/market-proceeds에서 진행한다. 미게시 codex/content-catalog 848f8b는 별도로 보존하고 이번 기능에 섞지 않는다.

목표는 기존 내 매물 화면에서 판매된 매물의 대금 수령을 요청하고 실제 서버 결과를 표시하는 것이다. 기존 sp_bazaar_claim의 판매자·SOLD·READY 검사와 동일 transaction 지급/CLAIMED 전환을 재사용한다. 거래 등록/구매/취소/배송, 새 경제 규칙·수수료·DB 스키마는 제외한다. 수령 완료 여부나 잔액을 추정하지 않는다.

서버 분석은 MARKET_CLAIM_CONTRACT.md, 구현은 그 확정 wire와 수명·소유권 경계를 따른다. 서버/ClientCore 변경도 허용된 후보 구현·로컬 검증 범위이며 게시 직전 Slack 승인과 플랫폼 통제를 유지한다. 직접 DB 테스트 데이터 생성·재시딩은 자동 수행하지 않는다.

소유권: 서버 분석 담당은 계약 문서만, 지정 구현 담당은 CoreLib/CacheLib/ClientCore와 자동 테스트, Coordinator는 Unity 거래소 UI/Editor 통합·실행 검증·공개 원본·Git을 맡는다. 독립 리뷰는 고정 diff를 읽으며 제품 코드 쓰기 금지. Editor 조작은 Coordinator 단독이다.

완료 조건: 서버 세션에 묶인 캐릭터로만 요청, request/listing 상관관계 보존, 기존 DB의 중복 지급 방지 유지, 큰 금액 손실 없는 전달, 중복 클릭/늦은 응답·연결 종료 처리, 서버 확인 뒤에만 수령 결과 표시. 알 수 없는 결과는 성공/실패를 단정하거나 자동 재시도하지 않는다.

검증은 구현·독립 리뷰 후 직접 영향 자동 2~3 시나리오와 실제 UI 흐름 1회로 모은다. 기존 거래소 검색·내 매물은 같은 흐름에서 확인한다. 먼저 읽기 전용으로 지정 계정의 정산 가능 매물이 있는지 확인하고 없으면 성공 실증을 주장하지 않는다. 서버 빌드·ClientCore 컴파일은 중간 확인만 하며 전체 회귀를 실행하지 않는다. 대표 캡처 최대 2장, 검증된 범위만 공개 사이트에 추가한다.

PR은 기능 전체를 하나로 모으고 준비된 diff·리뷰·검증 근거로 게시 직전 Unity Coordinator 앱에 짧게 승인 요청한다. 이전 승인 회신은 재사용하지 않는다. 완료별 재개 승인은 요구하지 않는다.
