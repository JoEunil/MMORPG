# C09 거래소 조회 — 검증 결과

## 상태와 대상

**검증 완료:** 기존 필드 캐릭터가 거래소의 판매 중 매물을 유형별·페이지별로 조회하고, 실제 서버 응답이 UI와 일치하는 것을 확인했다. 읽기 전용 조회만 연결했다. 매매·등록·취소·수령·DB seed·재화 정책 변경은 없다.

검증 대상은 `df172f6` 기준 C09 작업 트리의 동결 파일이다. 전달 후보는 PR28 수정 `c57127bb47c755eeb5d644b8f6f7e714f5320eb9`와 C08 통합 `68233678dac27a1fd69b987a8d327075ff8f65ed`를 보존하고, 검증한 C09 파일을 해시 일치 확인으로 복사해 구성한다. 커밋과 원격 전달 상태는 HANDOFF.md와 GIT_DELIVERY_STATUS.md에 기록하며, 이 문서만으로 게시·병합을 완료했다고 주장하지 않는다.

## 완료 근거

- 실제 Windows 마우스 입력으로 로그인 후 `MARKET`을 열어 유형1/페이지0, 유형2/페이지0, 유형3/페이지0, 다음 페이지1, 새로고침, 이전 페이지0을 조회했다. 창을 닫고 다시 열어 조회한 뒤 정상 로그아웃까지 완료했다. 7개 응답 모두 성공했고 `uiMatch=True`였다. 물약 30행, 무기/방패 12행, 방어구 빈 결과 5회가 서버 결과와 화면에서 일치했다. 플레이어 위치 `(103.061752, 11.0422964)`, HP 9975, MP 10000은 흐름 동안 변하지 않았다.
- 별도 read-only 확인에서 기존 매물은 조회 전후 물약 42, 무기/방패 12, 방어구 0행이었다. 행·재화·아이템 쓰기는 없었다.
- C09 관련 Unity 자동 배치 83/83(0.41초)와 TCP 영향 회귀 4/4(1.56초)를 통과했다. C++ 회귀는 기존 52개와 PR28 통합 추가 1개를 각각 확인해 53개가 통과했다(기존52개를 최종 통합 후 재실행한 것은 아님). 이들은 서로 다른 검증 묶음이며 하나의 전체 suite 재실행으로 합산하지 않는다.
- Unity DLL SHA256: `BD66C95F7DD34DE4F98D75632975B86A11157C56422997EA01A41C1EC184D62A`. 최종 Scene SHA256: `6B5359B154BA09DCD6A7DCEB5037A2B0E4A69B0FADB753F20D943F58F4BC735F`.
- 후보 서버 SHA256 `ABA9491459EA2444D8862199104DAD8A8ADDBD19AA52687FBE085C9CC2C123F8`는 2026-10-19에 PID 36748로 실행됐고, 시작 시 오류/stderr 0 및 무접속 상태를 확인했다. C08 정상 종료 중 기존 IOCP 995×8/10038×8이 guard를 멈춘 이력은 보존했다. 프로세스·포트 부재, WAL 0, read-only DB 상태 확인 후 검토된 별도 start-only 기동을 한 번 수행했다. guard 변경·강제 종료·DB 쓰기는 없었다. C09 종료 구현은 바뀌지 않았으며 `CancelIoEx` 1168 오류 2건은 남아 있다.
