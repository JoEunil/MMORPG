# 첫 사냥의 성장·아이템 기획 초안

작성: 2026-10-28. **기획 제안이며 구현·밸런스·서버 확장 승인이 아니다.** 사용자 선택은 성장·아이템 기획을 먼저 진행한다는 범위 선택이며 아래 수치나 기능 선택까지 확정한 것으로 해석하지 않는다. 이번 산출물은 소스 읽기와 문서 작성뿐이다. 서버·DB·게임 코드·Unity 실행·몬스터 AI·스폰 변경은 없다.

추천 순서는 **B 한 묶음 완성 → C의 획득·사용 전체 흐름을 다음 후보로 검토**다. 이는 예정 작업 확정이나 서버 수정 권한이 아니다. A는 완료된 기반이며 신규 성장 작업의 추천안이 아니다. B/C는 사용자 범위 선택 이후 구체화하고 모두 필수로 묶지 않는다. B의 설계 범위는 초기 몇 레벨의 기준·한 가지 성장 효과까지로 한정하며 전체 레벨 곡선을 먼저 만들지 않는다.

기술 작업 순서는 B의 레벨 전환 → HP포션 사용 계약 → 사냥 직접 지급 계약으로 나눌 수 있다. HP포션 사용만 먼저 구현한 단계는 신규 플레이어의 완결된 아이템 경험으로 보고하지 않는다. 사용과 획득을 함께 검증한 뒤 C가 완료되며 MP포션은 같은 계약을 재사용할 수 있는지 확인해 뒤에 붙인다. 장비·바닥 드롭은 이 묶음에서 미룬다.

## 추천 B의 한 번의 플레이

1. 기존 캐릭터로 필드에 진입해 Lv·누적 EXP·HP/MP를 확인한다. 이미 성장한 캐릭터의 데이터를 초기화하지 않는다. 초기 성장 확인은 별도로 허용된 전용 계정의 상태를 기준으로 한다.
2. 기존 이동과 Z/X/C로 일반 몬스터를 사냥한다. 새 퀘스트 수락·임무 패널·보상 수령 버튼은 필요 없다. 기존 마을→사냥터 동선을 이용하되 만남 좌표·처치 시간을 보장하지 않는다.
3. 처치 뒤 서버가 보내는 EXP 증가를 확인한다. 다음 레벨 기준을 넘으면 서버 확정 level 및 선택한 성장 효과가 갱신된다. 클라이언트는 미리 레벨이나 능력치를 올리지 않는다.
4. 같은 적과 한 번 더 교전해 성장 효과를 확인하고 마을로 돌아간다. 새 귀환 기능은 추가하지 않는다.

**보상 리듬 제안:** EXP는 기존처럼 매 처치 확정 지급하고, 첫 레벨은 긴 반복 사냥 전에 한 번 경험하도록 맞춘다. 초기 목표는 일반 몬스터 약 3~5회 처치 안의 첫 변화다. 이 횟수는 미승인 조정 목표이며 현재 데이터의 레벨 기준이 아니다. 기존 캐릭터 공격력·생존·실제 처치 시간을 확인한 뒤 필요 EXP를 정한다. EXP10/30을 변경해 맞춘다고 미리 정하지 않으며 ID2의 EXP300을 첫 목표의 필수 경로로 삼지 않는다.

**성장 효과 제안:** 첫 구현에서는 레벨에 따른 최대 HP 증가 한 가지만 우선 비교한다. 방어 공식·새 스킬·장비 능력치를 함께 추가하지 않는다. 증가량, 레벨업 때 현재 HP를 함께 회복하는지, 전체 성장 상한은 아직 정하지 않았다. 기존 서버에 성장 규칙이 있다면 그 규칙을 먼저 제시하고 이 제안으로 덮지 않는다. 현재 HP를 자동 전회복하는 연출도 승인 전 넣지 않는다.

**데이터 정책 제안:** 현재 누적되는 EXP는 총 누적 EXP로 유지하고 레벨별 누적 임계값과 비교하는 방식을 우선 제안한다. 레벨마다 EXP를 0으로 돌리는 방식으로 확정하지 않는다. 초기 기획의 목표 레벨과 운영 최대 레벨은 구분한다. 기존 저장 레벨이 초기 기획 범위보다 높아도 낮추거나 EXP를 초기화하지 않는다. 기존 높은 레벨과 누적 EXP의 불일치, 한 번에 여러 경계 통과, 상한 도달 시 EXP 정책은 구현 전에 정한다. 최대 HP 효과는 재접속 시 level에서 재계산할지 저장 범위를 바꿀지 분석과 함께 정한다.

**화면·입력:** 기존 Lv/EXP와 HP/MP 표시를 이용한다. 다음 레벨 필요량은 서버와 공유되는 확정 기준이 있을 때만 표시한다. 기존 Z/X/C·I/B를 유지하며 새 성장 창·스탯 배분·스킬 해금 버튼은 만들지 않는다. 레벨 변화 알림이 필요하면 실제 서버 level 변화에만 연결한다.

## 아이템의 목적 선택

현재 다섯 아이템은 가방에서 확인하고 기존 거래로 다루는 대상으로 설명할 수 있다. 전투 효과는 아래 중 선택하고 서버 범위를 확인하기 전까지 약속하지 않는다.

| 방향 | 플레이 목적 | 범위 판단 |
| --- | --- | --- |
| 회복 아이템 우선 — 추천 | HP포션으로 다음 교전을 이어간다. 이후 MP포션도 필요할 때 같은 흐름을 검토한다. | C를 선택하면 HP포션 한 종류부터 획득→가방→사용→소비/회복을 완성한다. 새 재료·등급·골드 드롭은 필요 없다. |
| 장비 성장 우선 | 철검·철방패·가죽갑옷을 얻고 실제 전투 성능 차이를 확인한다. | 장착·해제·슬롯·수치·영속화·현재 장비 표시가 별도 범위다. 첫 저비용 후보에서는 미룬다. 이름과 아이콘만으로 공격/방어 효과를 붙이지 않는다. |
| 기존 거래 대상으로 유지 | 소유 수량을 보고 기존 거래소에서 사고판다. | 신규 전투 효과 없이 기존 계약을 유지한다. 사냥 드롭이 생긴다는 뜻은 아니다. |

C를 선택하는 경우 **일반 몬스터 처치 → 기존 HP포션을 가방에 직접 지급 → I로 선택·사용 → 수량 감소와 HP 회복 → 다음 교전**을 하나의 확장 후보로 제안한다. 바닥 아이템이나 줍기 키를 만들지 않는다. 획득 경로는 현재 없으며 새 서버 정책·지급 경로가 필요하다. 기존 거래소 구매나 계정에 미리 넣은 테스트 물약을 신규 플레이어의 지속 공급원으로 설명하지 않는다.

보상 빈도는 낮은 확률의 희귀 드롭보다 **짧은 사냥 안에 용도를 확인할 수 있는 확정 보상**을 추천한다. 어떤 처치에 얼마나 지급할지는 저장·가방 용량 실패 정책과 생존 균형을 정한 뒤 제안한다. 현재 서버에 개인별 처치 횟수나 첫 보상 이력이 있다고 가정하지 않으며, 첫 사냥 전용 보상을 위해 새 퀘스트/이력 시스템을 만들지 않는다. 포션 회복량·재사용 대기·전투 중 허용 여부 역시 미승인이다. 무한 공급으로 생존 긴장을 없애거나 거래 품목이 급증하지 않도록 회복량·공급량은 함께 조정한다.

## 필요한 서버 분석 근거

병행 분석으로 지원 유무는 위와 같이 확인했다. 다음은 선택 뒤 정해야 하는 정책과 분석 근거의 연결 지점이며 구현 요청이 아니다.

- B: 누적 임계값·성장 효과·최대치/현재치·기존 저장 데이터 호환 정책을 정하고 기존 snapshot/delta와 정상 종료 저장으로 필요한 의미가 충족되는지 확인한다. 매 처치 내구화가 필요하면 비용을 별도 제시한다.
- C 사용: 외부 요청/결과와 서버 확정 소비·회복의 원자성, 재시도·재접속 때 중복 소비/회복 방지 범위를 정한다.
- C 획득: 내부 인벤토리 증감을 그대로 보상 API로 부르지 않는다. 처치 지급의 중복 방지·가방 가득 참·저장 실패·연결 끊김 정책과 서버/캐시 책임을 정한다.
- 보상 범위는 기존 막타 개인 지급을 기준으로 하며 공동 분배·오프라인 보상은 확장하지 않는다.

| A 기존 기반 | 처치에 참여해도 막타가 아니면 지급을 보장하지 않는다. 보상받은 캐릭터의 누적 EXP는 서버 확정치로 표시한다. | 접속 실패/미수신을 EXP0이나 지급 완료로 바꾸지 않는다. 보존은 실제 저장 계약과 대조한다. |
| B 선택 시 | 확정 필요 EXP 경계를 넘으면 level과 선택한 성장 효과가 한 서버 상태로 반영되고, 재접속 뒤 그 상태를 유지한다. 경계 미만에서는 레벨 변화가 없다. | 클라이언트 예측 상승·중복 레벨 효과를 금지한다. 사망과 레벨 전환이 겹친 경우 HP 정책을 확정한 뒤 구현한다. 끊김 뒤 보상을 재청구하는 버튼을 만들지 않는다. |
| C 선택 시 | 지정 조건의 처치 보상이 실제 가방 수량으로 늘고, HP포션 사용 성공 시 서버가 수량 감소와 HP 회복을 확정한다. 재접속 뒤 두 값이 정합하다. | 보상 가방 가득 참, HP가 가득 참/사망, 연속 사용, 중간 끊김의 정책을 서버와 확정한다. 실패 때 가짜 수량/회복을 보여주지 않으며 닫기만으로 사용하지 않는다. |

미선택 B/C의 수용 조건은 현재 클라이언트 결함이나 필수 개발 목록이 아니다. 구현 후 검증은 선택된 정상 경로와 가장 큰 실패 위험에 한정해 2~3개 시나리오로 정한다. 레벨업/드롭/회복·전투 균형은 이번 문서 작업에서 미실행·미평가다.

## 의사결정 지원 담당에게 전달할 질문 묶음

1. 첫 신규 묶음의 끝을 어디로 잡을까: **첫 레벨업(B, 추천)** / 포션 획득·사용(C). 둘 다 서버 확장이 필요하며 A는 이미 있는 기반이라는 점을 함께 제시한다.
2. 아이템의 첫 전투 목적은 **회복(추천)** / 장비 성능 / 기존 거래 대상으로 유지 중 무엇일까. 첫 선택이 B라면 이 답변은 후속 후보의 방향이며 즉시 구현 범위로 합치지 않는다.

세부 임계값·포션 회복량·드롭 빈도마다 질문하지 않는다. 선택 후 기존 서버 근거와 실제 플레이 소요에 따라 담당자가 작은 수치안을 묶어 제안한다. 사용자 답변은 의사결정 지원 담당이 선택 묶음과 적용 범위에 연결하고, 선택안 검수와 범위 확정은 Coordinator가 통합한다. 현재 답변 수신·승인 기록은 없다.
