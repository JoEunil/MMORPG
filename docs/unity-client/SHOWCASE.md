# AI-AGENT Unity 클라이언트 구현 작업

기존 게임 서버와 직접 만든 2D 클라이언트를 바탕으로 AI Agent에 3D 클라이언트 구현을 맡겼습니다. 요구와 플레이 피드백으로 수정한 과정을 담았습니다.

## 이번 작업의 결과

기존 클라이언트의 이동·몬스터·스킬·채팅·월드 진입을 3D 화면으로 연결하고, Unity에 없던 인벤토리·거래소도 서버에 연동했습니다. 사용자는 우선순위와 화면·조작 방향을 정했고, Agent는 필요한 조사·구현·아트·리뷰·검증을 맡아 실행 피드백을 반영했습니다.

## 먼저 만든 기반: 기존 2D Unity

기존에 직접 구현한 2D 클라이언트에는 이동·몬스터·스킬·채팅·월드 진입이 들어 있었습니다. Unity 인벤토리와 거래소 화면은 없었습니다. 이번 작업은 이 기반과 서버를 이어 3D 클라이언트로 확장했습니다.

![기존에 직접 구현한 2D Unity 클라이언트](../../site/media/legacy/unity-client.png)

## 선택한 방향을 결과로

아트·기획을 자세히 지시하기 어려운 항목은 여러 안을 비교하고, 사용자가 고른 요소를 묶음 작업에 반영했습니다. 아래는 실제 선택 기록의 화면이며 게임 플레이 장면은 아닙니다.

![전투 표현의 두 방향을 비교한 선택 화면](../../site/media/releases/2026-10-25/decision-support-combat.png)

전투·마을·사냥터·UI의 화면 시안과 전투 안내, 길 진입, 가방 상세 구성을 함께 비교했습니다.

![HUD의 미니맵·스킬·HP와 MP 표현을 비교한 시안](../../site/media/releases/2026-10-26/hud-options-comparison.png)

선택 시안은 방향을 정하기 위한 예시입니다. 실제 적용 화면과 기능별 이력은 [전투와 상태 UI](/MMORPG/work/player-hud/)에서 확인할 수 있습니다.

## 작업 방식을 바꾼 이유

요구를 구체적으로 전달하고, 실행 결과를 사람이 확인하는 과정이 필요했습니다. 특히 조작감과 아트 방향은 테스트 통과만으로 판단하기 어려워 비교 시안과 실제 플레이 피드백을 함께 사용했습니다.

[작업 중 느낀 점과 바꾼 방식 보기](/MMORPG/experience/)

## AI Agent 워크플로우

사용자는 목표와 우선순위를 정하고 결과를 판단합니다. 총괄 Agent는 필요한 역할을 배정하고 구현을 통합합니다. 모든 역할을 매번 실행하는 방식은 아닙니다.

### 에이전트 구성

- 사용자 — 목표·우선순위를 정하고 선택안과 결과를 검토
- 총괄 Agent — 범위 정리, 배정, 통합
- 의사결정 지원 Agent — 기획·아트 비교안과 선택 답변 정리
- 기획 Agent — 플레이 흐름과 완료 조건 구체화
- 서버 분석 Agent — 기존 서버 기능과 통신 규칙 확인
- 구현 Agent — Unity 화면과 서버 연결 구현
- 아트 Agent — 캐릭터·배경·UI 표현 개선
- 리뷰 Agent — 변경 내용을 독립적으로 검토
- 종합 검수 Agent — 기획·아트·UI·UX·조작 관점의 판단 지원
- 테스트 Agent — 정한 범위를 입력과 서버 응답으로 확인
- 기록 Agent — 확인된 결과와 화면을 공개 자료로 정리

## 하나의 기능이 만들어지는 흐름

요구를 확인 기준으로 정리하고, 필요한 역할이 구현과 검토를 진행한 뒤 바뀐 부분을 확인합니다. 기획·아트 방향이 불명확하면 선택안을 비교하고, 선택 답변을 기다리는 동안 독립 작업을 이어갑니다.

### 작업 흐름

- 목표와 확인 기준 정리
- 방향 비교 — 불확실성이 큰 판단은 2~3개 안의 장단점을 종합 검수합니다. 기술 선택은 승인 범위에서 총괄이 정하고, 중요한 기획·아트 방향은 사용자가 고릅니다.
- 선택한 방향을 구현하고 독립 리뷰
- 변경된 동작 중심의 검증
- 종합 검수와 결과 정리

### 피드백이 돌아오는 방식

- 코드 리뷰나 테스트에서 문제가 나오면 근거와 함께 원 구현 담당에게 돌려 수정합니다.
- 종합 검수 피드백도 같은 제작 담당이 반영하고, 영향받은 부분을 다시 확인합니다.
- 사용자 선택과 실제 플레이 피드백은 이후 작업의 조건에 반영합니다.

## Agent 활용 지표

새 Agent 실행은 새로 만든 Agent에 작업을 맡긴 횟수, 후속 작업 실행은 기존 Agent를 다시 실행한 횟수입니다. 전체 실행은 두 수의 합이며 메시지·테스트·토큰 사용량을 뜻하지 않습니다. [전체 역할별 집계 보기](/MMORPG/process/#agent-usage)

## 지침 변경 이력

- 실제 게임 화면과 조작 경험을 중심으로 클라이언트 범위를 구체화했습니다.
- Unity에서 만든 맵 데이터를 서버가 함께 쓰는 흐름을 추가했습니다.
- 기획·아트는 샘플을 비교해 선택하고, 관련 작업을 묶어 제작하도록 바꿨습니다.
- 작은 변경을 잘게 게시하기보다 관련 구현을 모아 리뷰와 필요한 검증을 진행하도록 정리했습니다.
- 검수 피드백은 원 구현 담당이 수정하고, 같은 검수 담당이 영향 부분을 다시 확인하도록 했습니다.

큰 변화의 배경과 전체 기록은 [작업 과정과 지침 변경 이력](/MMORPG/process/#execution-flow)에서 볼 수 있습니다.
