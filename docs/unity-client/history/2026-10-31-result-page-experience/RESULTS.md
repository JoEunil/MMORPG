# 결과 페이지와 의사결정 절차 개편 — 2026-10-31

## 지침 변경

기존 지침에는 비교 시안·담당자 수정은 있었지만 기술 대안의 사전 평가와 같은 실행 인스턴스에 피드백을 반환하는 도구 경로는 분명하지 않았다. WORKFLOW에 불확실성이 큰 판단의 대안2~3개→동일 기준 종합 검수→선택안만 구현, 그리고 피드백 원문·후보·파일·확인 조건을 원담당자에게 전달하는 경로를 추가했다. 종료한 담당자는 followup_task로 재활성화하며 같은 검수자에게 영향 부분을 재검수한다. 명확한 작은 수정에는 이를 강제하지 않는다.

기술 선택은 기존 승인 범위에서 총괄, 중요한 기획·아트 방향은 사용자에게 맡긴다. ToT의 아이디어를 참고한 운영 규칙이며 정식 탐색 알고리즘을 구현했거나 과거부터 실행했다고 주장하지 않는다. 모델·권한·자동 라우터를 바꿨다고 보고하지 않는다. 일회용 제작 브리프는 작업 폴더에만 보관했고 영구 지침으로 복제하지 않았다.

## 실제 작업 chain

1. 같은 조건의 결과 우선/사례 우선/기존 압축 세 안을 Astra가 비교해 결과 우선을 추천했다.
2. 기록 Agent가 SHOWCASE·EXPERIENCE·공개 가이드를 작성하고 구현 담당이 기존 Python 생성기와 CSS를 연결했다. 기존 사용자 AI-REFLECTION.md와 게임 기능 원본은 보존했다.
3. 모바일 소개 길이와 근거 없는 일반론은 같은 기록 Agent에게 피드백을 전달해 수정했다.
4. Astra 최종1차는 기술 선택을 모두 사용자에게 넘기는 것처럼 보이는 문구, 실제 시안 대신 지침 이력으로 연결되는 링크를 필수 수정으로 반환했다. 같은 기록 Agent가 수정했고 홈 안의 자기참조 링크도 제거했다.
5. 영향 구간의 실제 브라우저 근거를 보완해 같은 Astra가 최종 재검수했다. 판정 통과, 필수 잔여0이다.

## 구현과 확인

홈은 목적·기여 범위·대표 결과를 먼저 보여준다. 회고는 /experience/, 역할·절차·지표·큰 지침 이력은 /process/로 분리했다. 기존 기능 상세·화면 이력·옛 거래소 경로·홈 앵커의 안내를 유지했고 결과 제목과 이미지를 상세로 연결했다. 새 EXPERIENCE 원본도 기존 Pages 빌드 트리거에 포함했다. 생성 HTML은 빌드 결과이며 수동 편집하지 않았다.

기존 빌더의 전체 로컬 링크·앵커·미디어 검사를 통과했다. 소스·필수 피드백 변경 후에만 다시 빌드했다. 실제 in-app browser에서 데스크톱1280×720, 모바일390×844 viewport의 홈·회고·과정 가독성·가로 넘침과 탐색을 확인했다. 결과 이미지에서 거래소 상세로 이동하는 것도 확인했다. 모바일 검사는 viewport 모사이며 물리 모바일 기기 검증은 아니다. 브라우저의 PageDown 도구 실패는 지원되는 스크롤로 대체했고 제품 오류로 집계하지 않았다.
