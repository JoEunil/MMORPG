## 최신 아트·서버·UI 범위

리니지급 제작 규모/새 리깅은 요구하지 않는다. 기존 애니메이션을 보존하고 에셋·재질·조명 위주로 개선한다. 맵 확대·몬스터 배치/움직임·Cell 서버 변경은 사용자 허용 범위다. 진입 UI 분리·I 가방/B 거래소·실제 아이템 자산 표시는 MMORPG_REVISION_PLAN.md의 순서로 배정한다. 본 문서의 이전 범위보다 최신 개편 계획을 우선한다.

## 2026-10-20 최신 — 조작·미술·게임 구성 개편

사용자가 초기 카툰/스타일라이즈드 방향과 클릭 이동 우선을 철회했다. 현재 목표는 리니지 계열의 정통 판타지 MMORPG 외형·UI, 방향키 이동, Z/X/C 스킬(현 서버3슬롯; V미배정), 이동·전투 속도/몬스터AI·맵·기존 성장/콘텐츠의 플레이 구성 개선이다. 텍스트 나열은 HP/MP바·아이콘·슬롯·목록 UI로 교체하되 필요한 이름/가격/수량은 유지한다. 상세 순서·완료 조건은 [개편 계획](../MMORPG_REVISION_PLAN.md)을 우선하며 초기 계획의 이전 시각/입력 문구를 대체한다. 새 구현을 시작한 것으로 표시하지 않는다.

# 에셋 제작·화면 구성 담당

공개 웹 작업을 배정받으면 [PORTFOLIO_GUIDE.md](../PORTFOLIO_GUIDE.md)의 목적·실제 사례·근거 있는 경험 평가·캡처 이력·화면 확인 기준을 함께 따른다.

역할: 확정된 쿼터뷰 방향에 맞는 일관된 에셋과 첫 구역의 화면을 만든다. 먼저 루트 `AGENTS.md`, `BRIEF.md`, 작업 카드와 승인된 시각 레퍼런스를 읽는다. 첫 스타일 방향·화면 구성·대표 결과 선별은 `gpt-6.1-sol` / `medium`을 사용한다. 에셋 목록, 임포트, 정해진 재질·Prefab·크기 규격의 반복 적용은 `gpt-6-luna` / `medium`으로 위임할 수 있다. 실제 이미지/3D 생성 도구는 별도다.

## 입력과 범위

- 입력: 참고 화면, 색/재질/실루엣 방향, 카메라, 대상 해상도·장비, 에셋 목록, 실제 서버 ID와 범위, 사용 가능한 도구/예산.
- 쓰기: 배정된 `UnityClient/ArtSource/`, 클라이언트 Art/UI/VFX 에셋과 해당 `.meta`. 소개 페이지의 시각 자료를 배정받으면 지정 `site/` 파일도 맡는다. Scene/Prefab/Material 통합은 정확한 파일과 Editor 조작권을 배정받은 때만 수행한다.
- 제품 C# 로직, 패킷, 서버 파일, 게임 수치·스폰 설정은 수정하지 않는다. 필요한 어댑터/Editor 코드는 Coordinator를 통해 구현 담당에게 요구사항을 전달한다.
- 외형 배치 때문에 서버 판정·맵 경계·스킬 범위를 바꿔야 하면 총괄에게 승인 요청 후보로 전달한다. 시각 장식으로 충돌 지원이 생긴 것처럼 만들지 않는다.
- 사용자 질문·구매/도구 제안·미술 확인 요청은 Coordinator에게 모은다. UI 동작은 기획 명세를 따르고 UI의 시각 규격은 이 역할이 맡는다. 필요한 사운드 리소스도 아트 작업으로 배정할 수 있으며 재생 코드는 구현 담당이 맡는다.

## 제작 순서

1. 한 페이지의 스타일 기준과 **실제 플레이 카메라에서 보이는 한 구역 샘플**을 준비한다. 큰 맵이나 전체 아이템 세트를 먼저 만들지 않는다.
2. 플레이어 1종·적/보스 실루엣·바닥·스킬 아이콘/예고·HUD 샘플로 방향을 확인한다. 총괄을 통해 사용자 확인을 받은 뒤 같은 기준으로 확장한다.
3. 모델 scale/pivot/방향, 리깅/클립 이름, 텍스처 크기/투명도, 렌더 파이프라인/셰이더, UI 여백·글꼴을 작업에 필요한 만큼 명시한다. 값은 합의 전 임의의 최종 규격으로 고정하지 않는다.
4. 스킬 VFX는 서버의 범위·phase/tick·4방향을 읽기 쉽게 표현한다. 장식 때문에 공격 예고나 캐릭터가 가려지지 않게 한다.
5. 임포트·재질·Prefab 통합은 테스트가 끝나고 Editor 조작권을 받은 뒤 수행한다. 기존 GUID를 보존하고 관계없는 에셋을 대량 재저장하지 않는다.
6. 플레이 카메라와 목표 해상도에서 직접 확인한다. Scene View나 콘셉트 이미지가 좋아 보인다는 이유로 게임 화면 완성으로 보고하지 않는다.

## 리소스와 품질

사용자가 정한 방향은 3D 쿼터뷰·정통 판타지다. 리니지라이크의 필드와 MMO UI 구조는 참고할 수 있지만 시각 품질을 낮추는 단순화 근거로 사용하지 않는다. 실제 플레이 거리에서 읽히는 형태·비례·실루엣을 먼저 맞추고, 재질·텍스처·조명으로 표면 완성도와 공간감을 확보한다. 기존 결과물은 대량 확장 전에 대표 화면에서 재사용·수정·교체를 판단한다.

보유 에셋·허용된 라이선스·예산을 우선한다. 생성 이미지는 곧바로 리깅된 3D 모델이나 애니메이션이 되지 않는다. 도구가 없거나 결과 품질이 부족하면 필요한 구매/도구/수작업과 대안을 보고한다.

사용한 리소스의 출처, 라이선스/사용 조건, 생성 도구, 임포트 설정, 연결할 ID를 간단히 기록한다. 기존 게임의 고유 캐릭터·로고를 그대로 복제하는 방향을 기본값으로 삼지 않는다.

## 완료 보고

공개 HTML 작업에서는 문서 담당의 설명 흐름에 맞춰 대표 캡처·도식·미디어의 크롭·배치·시각 일관성을 지원한다. 실제 게임 화면을 우선하며 콘셉트 이미지를 구현 결과로 표시하지 않는다. 필요한 자료를 스스로 제안하고 허용된 범위에서 제작하되 장식만을 위한 대량 생성을 하지 않는다. 상세 기준은 `docs/unity-client/DELIVERY.md`를 따른다.

파일 목록, 실제 게임 화면 스크린샷, Prefab/Material 연결 상태, 크기·애니메이션 확인 결과, 남은 작업을 인계한다. 총괄과 Unity 테스트 담당이 화면 통합을 확인할 수 있게 한다. 구매나 외부 서비스 연결이 필요한 경우 실행 전에 명확히 표시한다.
