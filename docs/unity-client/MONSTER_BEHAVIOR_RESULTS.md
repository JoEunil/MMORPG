# 몬스터 행동·이동 템포 결과

2026-10-20 작업 재개로 같은 플레이 경험 브랜치 codex/classic-mmorpg-motion에 통합했다. 기존 보간/예측2f99cb0 위의 후보이며 새 맵 기하나 로그인 화면 전면 개편 완료를 주장하지 않는다.

## 변경

- CoreLib WORLD_MOVEMENT_SCALE=.25, 플레이어 보충 예산 .25unit/50ms로 지속 이동5unit/s. CAP3는 구형1unit요청이 과속요청으로분류되어끊기는것을피하려고유지했다. 초과요청의기존예산클램프/보안경로·wire는그대로다. 클라이언트목표.25/50ms와화면5unit/s를일치시켰다.
- 몬스터 추적5/6/3unit/s, 배회3unit/s. 개체별seed로1~3초배회와0.5~1.5초멈춤/방향변경을선택한다. 생성점±6과현재셀을벗어나지않고추적뒤멀어졌으면돌아온다. 다른셀로의실제개체재등록은아직하지않는다.
- 생존/aggro상태에서카운터를한번씩증가시켜기존100tick=5초timeout이동작하도록수정했다. 대상소실은타이머도초기화하고보스공격간격은공격tick으로측정한다. 리스폰은배회상태/HP·위치·방향dirty를복구한다. 고정스폰총수·보상·DB데이터변경없음.
- I가방/B거래소는기존TogglePanel경로로열고닫으며포커스/입력창가드를적용했다. 기존root의미게시구매·취소UI는덮어쓰지않고동일한작은입력변경만적용했다. 화면분리와아이템그림을전패널에연결하는작업은남아있다.

## 검증

- 독립 계약/코드 리뷰 차단0. 추적속도/셀경계 검증누락은기존두번째시나리오에추가했다. Coordinator는한번선택하는배회/멈춤시간을1~3초/0.5~1.5초로조정해잔떨림을줄였다.
- Release MainServer와UnitTests 빌드exit0. 실제ZoneState::UpdateMonster/MoveToward 네이티브2시나리오모두PASS(배회속도/멈춤/다양성/영역/리스폰; 타이머/대상소실/강한몬스터추적.3tick/셀경계/보스간격/사망중타이머). 기존전체테스트는반복하지않았다.
- Unity컴파일completed·errors0. 영향받은C16OwnMotionTests1/1 PASS(0.07초). 화면이50ms에.25unit예측·작은서버보정은화면을덮지않음·취소수렴·큰보정/초기화). 변경없는원격보간·export/거래소회귀는반복하지않았다. I/B는컴파일/정적확인만했으며실키로통과했다고하지않는다.
- 실제입력미실행. 네이티브창조회후캡처가Unity화면대신다른게임/브라우저중첩을보여창활성화나키/마우스를보내지않았다. 입력검증배치에5unit/s기준·I/B/채팅가드를추가한다. 이는사람의재개권한을취소한것이아니며새승인질문은만들지않는다.
- 증거: root UnityClient/Builds/Monster-AI-Revision/build.txt, Captures/monster-ai-native.txt, monster-ai-own-motion.txt. MainServer는별도폴더빌드만완료했고실행/재기동/DB쓰기는0이다. 기존구매기능포함서버를기능이빠진브랜치바이너리로덮지않는다. 통합릴리스후보를준비한뒤한번에실제사냥배치로검증한다.
