## 성장 규칙의 저작·저장 방식

사용자 후속 결정으로 성장 규칙도 서버 C++ Data를 정본으로 둔다. 레벨별 누적 필요 EXP·승급 효과를 데이터 테이블로 관리하고 판정 코드가 조회한다. Unity가 규칙을 작성해 서버를 덮어쓰는 방식은 사용하지 않는다. 서버/클라이언트 공유는 [현재 데이터 경로](CONTENT_PIPELINE.md)의 서버 exporter→JSON→기존 Unity asset importer 방향으로 이어간다. 스킬·몬스터·성장 모두 같은 exporter/JSON formatVersion2/importer를 사용한다. GrowthData.h/Growth.inc의100행과 Unity 성장 필드는 구현했고, 실제 레벨업 로직은 후속 범위다.

Lv1~100 행·단조 증가 임계값·중복 레벨·수치 범위를 exporter/importer에서 검증한다. 초기 표는 누적 EXP=50×L×(L−1)/2, Lv1 증가량0/Lv2~100 최대 HP 증가량500이다. 초기 데이터 작성용 곡선이며 밸런스 확정이나 실제 승급 적용을 의미하지 않는다. 초기 EXP50/150·HP+500과 Lv4~100 곡선은 데이터 제안이며 수치별 분기를 코드에 하드코딩하지 않는다. DB는 캐릭터의 실제 level/누적EXP/현재·최대HP를 기존 필드에 저장한다. 새 DB 규칙 테이블·런타임 .dat 로더·핫리로드는 도입하지 않는다. 기존 저장 레벨/최대HP를 로그인 때 새 표로 재계산하지 않는 정책은 유지한다.

## 선택된 첫 묶음: 초기 레벨업

**마을→일반 몬스터 사냥→EXP 축적→첫 레벨업→성장 효과 확인→마을 복귀**를 첫 구현 후보의 플레이 흐름으로 잡는다. 실제 레벨·최대 HP 변화가 끝점이다.

1. 기존 이동·Z/X/C로 사냥하고 처치 보상 EXP를 받는다. 새 임무 수락·보상 수령 버튼은 필요 없다.
2. 필요 EXP 경계를 넘으면 서버가 level과 성장 효과를 함께 갱신한다. 기존 Lv/EXP·HP/MP를 사용하고 응답 전에 수치를 올리지 않는다.
3. 같은 적과 다시 교전해 생존 여유 변화를 확인한다. 아래 검토안의 효과는 최대 HP만 증가한다. 공격력·MP·스킬·스폰·몬스터 AI는 바꾸지 않는다.

### 첫 레벨업 정책 묶음 — 수치 미승인

| 항목 | 하나의 검토안 |
| --- | --- |
| 초기 구간 | Lv1→2는 총 누적 EXP50, Lv2→3은 총 누적 EXP150. EXP를 레벨마다 차감하지 않는다. |
| 보상 리듬 | EXP0의 Lv1이 ID0(EXP10)만 처치하면 첫 변화5회, 다음 변화 추가10회다. 산술 비교이며 측정한 시간·체감 균형이 아니다. 다른 몬스터·기존 EXP에는 횟수가 달라진다. |
| 성장 효과 | 새로 승급한 레벨당 최대 HP+500. Lv1→3을 한 보상에 처리하면 최대 +1000. 기존 최대 HP를 기준으로 더하며 기준 최대 HP를 새로 덮지 않는다. |
| 현재 HP | 살아 있으면 실제 최대 HP 증가분만 현재 HP에 더해 잃은 HP 양을 유지한다. 예: 6000/10000→6500/10500. 전회복하지 않으며 HP0은0으로 둔다. |
| 레벨 상한 — 사용자 확정 | 정상 성장 상한은 Lv100이다. Lv2/3은 초기 확인 구간일 뿐 성장의 끝점이 아니다. Lv100에서는 추가 승급하지 않으며 기존 EXP 누적 정책은 수치 한도 안에서 유지한다. 기존 저장 레벨이100을 초과하는 예외 데이터도 승인 없이 낮추거나 초기화하지 않는다. |
| 기존 저장 데이터 | 로그인 때 레벨·EXP·저장 최대 HP를 고치거나 HP 보너스를 다시 더하지 않는다. 기존 고레벨을 낮추거나 EXP를 초기화하지 않는다. |
| 승급 시점 | 향후 정상 처치 보상이 지급될 때 현재 level과 보상 반영 후 총 EXP로 판단한다. 기존 캐릭터도 로그인 때는 그대로 두고 다음 정상 보상에서 현재 레벨 이후의 성장표 경계를 Lv100 이내까지 처리한다. 이미 보유한 레벨의 보너스는 다시 지급하지 않으며 Lv100 이상은 추가 성장 보너스를 받지 않는다. |
| 여러 경계·수치 한계 | 한 보상에서 성장표상 통과 가능한 경계를 Lv100까지 모두 처리한다. EXP는 넓은 중간 계산 후 uint32 최대에서 포화시켜 감김을 막는다. HP도 넓게 계산해 실제 저장/전달 필드 상한 이내로 제한하고, 현재 HP에는 제한 후 실제 최대 HP 증가분만 더한다. 기존 비정상 HP/최대치의 자동 복구는 이 범위에 넣지 않는다. |
| 저장 | 바뀐 EXP/level/현재 HP/최대 HP를 기존 정상 disconnect·서버 정리 저장과 상태 전파에 연결한다. 실제 필드 포함은 구현 시 재확인한다. 매 처치 저장·충돌 시 WAL 보장·새 스키마는 약속하지 않는다. 비정상 종료 때 마지막 저장 이후 성장은 유실될 수 있다. |

HP+500은 기존 최대 HP10000인 경우5%의 증가이므로 체감은 아직 약할 수 있다. 신규 캐릭터 기본값과 실제 피해·교전 관찰을 보고 묶음 전체를 조정하며 개별 수치마다 새 선택 질문을 만들지 않는다. 저장 HP/MP 초기화나 공격/스킬 하향으로 성장을 강제하지 않는다.

## 선택된 후속 방향: 회복 아이템

추천 후속은 **일반 몬스터 처치→HP포션 가방 직접 지급→I에서 선택·사용→수량 감소와 HP 회복→다음 교전**이다. 현재 획득·사용은 없으며 서버 확장이다. 거래소 구매나 테스트 계정에 미리 넣은 물약은 신규 플레이어의 지속 공급원이 아니다.

기술 순서는 **레벨 전환→HP포션 사용 계약→처치 직접 지급 계약**이다. 사용만 구현한 단계는 완결된 아이템 경험으로 보고하지 않는다. 지급까지 연결한 뒤 MP포션을 같은 계약으로 다룰지 검토한다. 첫 레벨업과 포션 전체를 모두 첫 구현의 필수로 합치지 않는다.

희귀 확률 보상보다 짧은 사냥 안에 용도를 확인하는 확정 보상을 우선 비교한다. 어떤 처치에 몇 개를 주는지·회복량·재사용·전투 중 허용은 미정이다. 첫 보상 이력·처치 횟수 기능이 있다고 가정하지 않는다. 장비·바닥 줍기·새 재료·제작·상점·골드 드롭은 이 묶음에서 미룬다.

**회복 수요도 미평가다.** 기존 관찰 maxMP10000에 X/C 비용20이면 다른 비용·회복을 빼고 단순 계산상 약500회분이다. 현재 MP포션이 필요하거나 균형이 맞는다고 주장할 수 없다. 공급량·회복량·기본 능력치는 별도 조정 제안으로 다루며 저장 HP/MP 초기화나 스킬 하향으로 수요를 강제하지 않는다.

## 영향 책임과 향후 최소 검증

- 서버 전투/캐릭터 상태: 기존 막타 EXP 지급 지점에 승급·HP 변경·dirty field 전파를 연결한다. 보상 중복을 만들지 않는다.
- 기존 저장/로드: 정상 종료 저장의 변경 필드와 재접속 보존을 대조하고 로그인 시 성장 재적용을 막는다. 캐시/DB 직접 보정은 하지 않는다.
- ClientCore/Unity: 기존 snapshot/delta와 Lv/EXP·HP 표시를 재사용한다. 필요 EXP 진행률·새 성장 창·스탯 배분은 추가하지 않는다.

향후 검증은 다음 세 묶음으로 제한한다. 현재 통과한 테스트가 아니다.

1. Lv1/EXP40에 EXP10 지급→Lv2/EXP50·최대 HP+500·생존 HP도+500. 임계값 미만·한 번에 여러 레벨·Lv99→100/100 이후 상한·필드 상한도 같은 집중 단위검증에서 확인한다.
2. 기존 고레벨·높은 EXP의 낮은 레벨·HP0 상태에서 로그인 시 무변경, 다음 정상 보상 때 필요한 승급만 적용, 이미 보유한 레벨 보너스 재적용 없음·Lv100 이후 승급 없음·EXP 정책 유지를 확인한다.
3. 정상 처치 승급→기존 HUD의 서버 확정치 반영→정상 disconnect/재접속에서 EXP/level/HP/최대 HP 유지·추가 보너스 없음 확인. 충돌 내구성·균형 성공으로 확대하지 않는다.

관찰할 완료 조건은 다음과 같다.

| 범위 | 정상 결과 | 실패·재접속 기준 |
| --- | --- | --- |
| 첫 레벨업 | 확정 임계값 미만에는 승급 없고 경계 통과 시 level과 최대 HP/생존 HP 반영. 정상 재접속 후 정합. | 중복 성장·클라이언트 선반영 금지. HP0 보존·기존 고레벨/EXP 보존·로그인 보너스 재적용 없음. |

기존 막타 개인 보상을 유지하며 공동 분배를 확장하지 않는다. 다음 레벨 필요량은 확정 서버 기준과 연결할 때만 표시한다. 새 성장 창·포션 단축키는 기본 범위에 넣지 않는다. 구현 후 정상 경로와 가장 큰 실패 위험을 2~3개 시나리오로 확인한다. 이번 문서에서 레벨업·드롭·회복·균형은 미실행·미평가다.

## 방향 답변과 상세 정책의 구분

의사결정 지원 담당은 위 답변을 **레벨업 우선·회복 후속** 방향에만 연결한다. EXP50/150 이후 Lv100까지의 곡선·HP+500·기존 데이터 전환·저장 정책은 이 문서에서 새로 제안한 한 묶음으로 Coordinator의 리뷰 대상이다. 회복 아이템 구현이나 서버/DB 수정까지 허용됐다고 기록하지 않는다. 정책 검토 후 구체적 구현 범위를 별도로 정한다.
