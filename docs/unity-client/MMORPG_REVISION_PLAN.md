# 클라이언트 개선 순서

이 문서는 작업 선택 기준이다. 현재 진척·입력 허용·후보는 HANDOFF, 실제 권한은 AGENTS.md가 정본이다. 기존 완료율을 새 개편의 완료율로 재사용하지 않는다.

## 현재 방향

정통 판타지 쿼터뷰, 방향키 이동, Z/X/C, I가방/B거래소를 사용한다. 신규 리깅 없이 에셋·재질·조명·기존 파츠 모션으로 개선한다. 카툰과 클릭 이동 우선은 폐기했다. 품질은 모델 이름만 바꿔 확보됐다고 주장하지 않는다.

몬스터 AI는 사용자가 상태 머신/Cell간 이동/Wandering 정지와 이동 후 phase 시전으로 변경했다. A*는 적용하지 않으며 Agent 후속 작업으로 넣지 않는다. AI 통합/빌드/실행은 소스로 확인한다.

## 재작업을 줄이는 순서

| 순서 | 확인할 결과 | 범위 |
| --- | --- | --- |
| 1 | 실제 서버·ClientCore 계약과 기존 완료 근거 | 사용자 변경·좌표·속도·소유권·phase/경제 |
| 2 | 조작·보간/예측·충돌 일관성 | 서버 예산과 시각 상태 분리, 고무줄/잘못된 방향 방지 |
| 3 | 대표 게임 화면·VFX·아트 | 실제 카메라 비교 후 재질·지면·UI 확장 |
| 4 | 진입·HUD·가방·거래소의 일관성 | 기존 기능·아이템 자산·가격/수수료/재화 |
| 5 | 관련 최소 검증·결과 자료·전달 | 같은 후보를 묶어서 검증·큰 PR |

각 항목은 이미 끝난 관련 근거를 먼저 재사용한다. 위 표를 이유로 완료한 단계를 반복하거나 사용자 AI를 다시 구현하지 않는다. 관련 기존 미완료만 고르고 무관한 기능은 추가하지 않는다.

아트 방향 결정 전 대량 제작하지 않고 일반 UI/정리에는 필요한 역할만 배정한다. 실제 사용 모델·활성화는 AGENT_USAGE에 기록한다. 구매/도구 비용은 사전 확인한다.

이전 단계별 진척·70~80% 추정·A* 계획·각 사냥 관찰은 [감사 전 원문](history/2026-10-24-guideline-audit/README.md)과 기존 실행 결과에 보존한다.

## 다음 작업 묶음 — 채팅·패널 조작과 구역 복귀 (2026-10-27)

PR56 병합을 확인하고 최신 master에서 새 브랜치로 시작한다. 확정된 UI 배치·아트·I/B/Z/X/C는 유지하며 서버·사용자 몬스터 AI·ClientCore/DLL·wire·경제·DB는 변경하지 않는다.

- 구역 이동 중 확인이 끊긴 귓속말의 초안과 미확정 안내를 보존한다. 일반 수신이나 늦은 echo로 성공을 단정하거나 초안을 지우지 않는다. 전송 문구는 Trim 기준으로 비교하며, 같은 세션의 미확정 문구 재전송은 echo만으로 성공 확정하지 않는다. 자동 재전송은 하지 않는다.
- 채팅·가방·거래소의 Escape를 기존 Input System 경로로 맞춘다. 텍스트 편집 중 첫 Escape는 초안 보존·포커스 해제만 하고 패널은 유지한다. 다음 Escape는 열린 패널을 닫는다. TMP의 편집 전 원문 복원과 Update 순서에 의한 이중 처리를 방지한다.
- 구현 후 독립 리뷰와 직접 영향 검증을 한 묶음으로 수행한다. 검증 예산은 전환/늦은 echo, timeout 후 재전송, Input System·EventSystem Escape의 3개 이하이다. 기존 통과 테스트는 반복하지 않는다. 합성 입력과 물리 입력을 구분한다.

Astra 계획 자문은 최초 수정 필요 판정 후 위 조건을 보완해 통과했다. 사용자에게 다시 선택받을 기획·아트 방향은 없다. 구현·검증 성공이나 게시 승인을 뜻하지 않는다. 관련 후속 흐름을 완성한 후 큰 PR 후보로 묶고 최종 게시 직전에 Slack 승인을 요청한다.
