# AI-AGENT Unity 클라이언트 구현 작업 — 웹페이지 지침

공개 사이트 명칭은 **AI-AGENT Unity 클라이언트 구현 작업**이다. 제출 용도가 포트폴리오라는 설명과 사이트 이름을 구분한다. AI Agent 워크플로우를 설명할 때 일반 팀 프로젝트처럼 표현하지 않고, 사용자 목표·판단 → 총괄 에이전트의 전문 역할 배정 → 구현/독립 리뷰 → 작업 묶음의 실제 검증/수정 → 사용자 최종 확인의 주체를 명확히 한다. 기존에 사용자가 직접 구현한 Unity 화면은 출처가 확인된 기존 자료로 별도 표시하고 AI Agent 결과로 오인하게 섞지 않는다.

2026-10-19 사용자 작성안을 반영한 현재 기준이다. 공개 사이트의 목적·콘텐츠·화면 구성에서는 이전의 단일 AI 소개 페이지 지침보다 이 문서를 우선한다. 내부 기록과 게시 권한은 기존 WORKFLOW·DELIVERY 기준을 유지한다.

## 공개 웹페이지의 목적

포트폴리오 제출 시 별도로 전달할, **AI 에이전트 기반 게임 개발의 결과와 경험을 소개하는 사이트**다. 방문자가 결과물을 먼저 보고, 사람이 에이전트를 어떻게 활용했으며 그 과정에서 무엇을 배웠는지 이해할 수 있도록 만든다.

기존 서버 포트폴리오와 PPT의 설계 설명은 링크로 연결한다. 이 사이트에서는 AI 에이전트로 진행한 작업과 실제 결과에 집중하며 기존 설계 문서를 다시 옮겨 적지 않는다.

## 공개 콘텐츠 구성

- **결과물:** 대표 게임 화면을 첫 화면에 배치한다. 기능별 캡처·GIF에는 무엇을 조작했고 어떤 결과가 나타나는지 짧게 설명한다. 이미지를 충분히 크게 열어 보고 비교할 수 있어야 한다. 실제 화면과 동작의 근거 없이 완료를 주장하지 않는다.
- **에이전트 활용:** 사람이 정한 목표와 판단, 에이전트에 맡긴 작업, 결과를 검토하고 수정한 방식을 실제 작업 사례로 설명한다. 역할 이름과 절차를 전부 나열하는 것으로 대신하지 않는다. 사람이 한 일과 에이전트가 한 일을 구분한다.
- **경험과 평가:** 도움이 된 점, 기대에 못 미친 점, 직접 개입한 부분, 다음에 바꿔볼 방식을 정리한다. 사용자가 실제로 말한 경험과 확인된 사례를 근거로 쓰며, 사용자의 감상·만족도·생산성·학습 내용을 대신 만들어내지 않는다. 관찰된 사실과 사용자의 평가를 구별한다.

개발이 진행되면서 결과물과 회고를 추가한다. 모든 항목을 처음부터 채우거나 분량을 맞추려고 내용을 만들지 않는다. 근거가 없는 항목은 생략한다.

## 결과물과 화면 이력

현재 결과와 개선 중인 중간 결과를 방문자가 이해할 말로 구분한다. 예를 들어 지금의 거래소 숫자 출력 화면은 초기 조회 화면이며, 이후 실제 UI로 개선한 화면과 비교할 수 있게 남긴다. 미지원 동작을 완성된 기능처럼 표현하거나 캡처에서 오류를 지워 성공처럼 보이게 하지 않는다.

캡처에는 작업명·촬영일·보여주는 동작과 결과를 짧게 연결한다. 같은 기능을 개선할 때 새 화면을 추가하고 이전 화면을 보존한다. 날짜만 다른 동일 화면을 개선 사례로 만들지 않는다. 내부 버전·검증 근거와 공개 캡처의 대응은 내부 기록에서 관리하고 해시·빌드 정보를 공개 본문에 나열하지 않는다.

## 내부 기록과 공개 설명

C09·R01 같은 작업 ID, 승인 번호, PID, 해시, 원문 로그와 세부 상태표는 내부 기록에 둔다. 공개 제목과 메뉴에는 '인벤토리 조회', '다른 플레이어와 이동'처럼 방문자가 이해할 이름을 사용한다. PR·병합·승인 상태를 공개 화면의 알림이나 목차로 쓰지 않는다.

검증 근거는 무엇을 실제로 확인했는지 짧게 설명하고 필요한 상세 소스·문서 링크를 제공한다. 테스트 개수나 내부 작업 순서를 길게 나열하는 것으로 결과 설명을 대신하지 않는다. 계정·토큰·비밀 설정·개인 정보는 공개 자료에서 제외한다.

## 화면 구성과 구현

Markdown은 콘텐츠를 관리하는 수단이다. 문서의 제목 순서와 분량을 그대로 웹 화면으로 옮기지 않는다. 콘텐츠에 맞춰 대표 화면, 갤러리, 짧은 설명, 사례 비교를 다르게 배치한다. 각 본문의 원본은 한 곳에서 관리하고 생성 HTML을 별도로 편집하지 않는다.

한 페이지에 모든 내용을 담는 것을 완료 조건으로 삼지 않는다. 첫 화면은 결과와 핵심 소개에 집중하고 작업 상세·갤러리·활용 과정·회고는 링크로 탐색한다. 내용이 적은 빈 페이지를 구조를 채우기 위해 만들 필요는 없다.

동일한 카드나 슬라이드형 패널을 반복하기보다 게임 화면의 크기, 글의 위계, 여백으로 읽는 흐름을 만든다. 불필요한 장식 문구와 긴 설명을 줄인다. **대량 구현 전에 대표 화면과 갤러리 한 구간을 실제 브라우저에서 만들어 시각 방향을 확인하고 사용자에게 보여준다.** 이때 개발 전체나 다른 독립 작업을 멈추거나 별도의 승인 단계를 자동으로 추가하지 않는다.

## 개발 워크플로우에 반영

개발 작업 묶음을 검증한 뒤 문서 담당은 공개할 결과·사례·회고·캡처 후보를 갱신하고, 기존 구현·아트 담당은 작업 상세와 현재 화면·이력을 반영한다. 리뷰·테스트는 공개 범위와 근거, 실제 탐색·미디어·모바일을 확인한다. 공개할 변화가 없으면 그 이유만 내부 작업 기록에 남긴다.

사이트 갱신만을 위해 이미 통과한 게임 입력 검증을 반복하지 않는다. PR 전에는 실제 브라우저 미리보기와 선별 화면을 제공하고, 게시와 로컬 검증을 구별한다. 기존 PR 직전 Slack 최종 승인 및 master 기준 Pages 배포 정책은 유지한다.

## 완료 기준

처음 방문한 사람이 다음을 쉽게 찾을 수 있어야 한다.

- 실제로 만들어진 게임 화면과 동작
- 사람이 한 일과 에이전트가 한 일
- 확인된 AI 활용의 이점과 남은 문제
- 더 자세히 볼 수 있는 소스·문서 링크

데스크톱과 모바일에서 실제 캡처·GIF의 크기와 재생, 글의 가독성, 링크 이동과 돌아오는 흐름을 확인한다. GIF가 없는 작업은 실제 캡처를 사용하며 형식을 채우려고 새 영상을 만들지 않는다. 사이트의 게시 성공과 포트폴리오 콘텐츠의 완성도를 별도로 확인한다.
