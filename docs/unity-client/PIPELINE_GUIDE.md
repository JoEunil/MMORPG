# Agent 구성과 도구 적용

정책은 [AGENTS.md](../../AGENTS.md), 현재 상태는 [HANDOFF](HANDOFF.md)다. 문서 권장·설정 파일·실제 실행을 구분한다.

책임은 roles/*.md에서 관리한다. 종합 검수는 단계별 복합 상황 자문, 사용자 전달 전 선택안 검수, PR 묶음 마감 검수로 활용한다. 모드를 구분하고 쟁점을 묶어 세부 코드 리뷰·테스트를 대체하거나 반복하지 않는다. 미등록 상태라면 default 신규 인스턴스에 gpt-6-astra/medium, fork_turns=none과 해당 역할 지침·후보 근거만 명시한다. 실제 Astra 실행을 확인할 수 없으면 Sol 결과를 Astra 검수로 표시하지 않는다. 코드 개선은 기존 담당자의 업무이며 별도 프로필을 추가하지 않는다. 의사결정 지원 담당은 기획·아트 제작을 중복하지 않고 비교 묶음과 사용자 답변 연결만 맡는다.

프로젝트 [agents] 기본값은 gpt-6.1-sol/medium이며 반복 테스트·기록은 해당 역할의 Luna 설정을 사용한다. Coordinator 모델은 사용자가 앱에서 선택하며 프로젝트 설정으로 덮어쓰지 않는다. 복잡한 설계·동시성·서버 계약 분석/리뷰는 필요 근거와 파일 범위를 정해 Sol/high, 특히 어려운 통합 판단은 Astra/low~medium 작업으로 별도 배정할 수 있다. 모든 작업을 일괄 high로 올리지 않는다.

실제 배정 도구의 역할 정의와 TOML을 대조한다. 기존 실행 Agent의 재활성화가 새 모델을 적용한다고 가정하지 않는다. 고정 역할 설정을 호출 인자로 덮어쓸 수 없으면 지원되는 default/worker의 새 작업에 모델·추론·역할 지침을 명시하거나 설정 재로딩 후 해당 역할을 새로 시작한다. 모델을 명시한 별도 배정은 fork_turns=none으로 필요한 근거만 전달한다. 새 프로필이 등록되지 않았으면 대체 실행 경로와 미등록 상태를 기록한다.

Fast/Ultrafast와 모델 추론은 별개다. 현재 요청은 역할 모델과 배정 방식 변경이며 service_tier·요금 모드·권한은 변경하지 않는다. 실제 1.5배 완료 속도나 아트 품질 향상을 설정만으로 보장하지 않는다.

## 병렬 배정과 선택 대기

같은 역할 프로필은 서로 다른 작업을 맡는 여러 인스턴스로 동시에 배정할 수 있다. 의사결정 지원도 기획 비교·아트 자료 취합처럼 독립 책임별로 나눌 수 있다. 하나의 실행 인스턴스에 여러 메시지를 보내는 것은 별도 병렬 실행이 아니며, 각 인스턴스에 담당 파일과 결과 범위를 구분한다. 이 원칙은 모든 역할과 하위 배정에 공통 적용하며 실제 전체 슬롯과 비용 기준을 따른다.

- 첫 배정에서 범위·파일 소유권·의존 작업·완료 조건·최소 검증·복원을 정한다. 공통 파일과 Unity Editor는 한 명이 소유한다.
- 독립 기능이 있으면 총괄이 직접 전부 구현하는 대신 구현·아트·분석/선택 준비를 겹쳐 진행한다. 같은 기능의 최종 리뷰·검증은 구현 후보를 고정한 다음 맡긴다.
- 현재 관찰한 슬롯은 총괄 포함4개다. 예: 총괄1 + 구현1 + 아트1 + 분석/선택1, 완료 슬롯을 리뷰·테스트로 전환한다. 이 숫자를 프로젝트 cap으로 저장하지 않고 매 실행의 실제 슬롯을 따른다. max_concurrent_threads_per_session=2 제한은 되살리지 않는다.
- 의사결정 지원 담당은 보드와 질문을 반환하면 해당 실행을 끝낸다. 총괄이 비동기 질문을 한 번 게시하고 다른 일을 진행한다. 답변 도착 시 같은 담당에게 원문·묶음/개정·출처를 전달해 후속 실행한다. 대기만 하는 Agent·폴링·불필요한 역할 호출로 병렬성을 부풀리지 않는다.
- 검증·Unity 조작을 넘기면 총괄은 같은 Editor를 건드리지 않는다. 그동안 코드 읽기·다른 파일 구현·문서/선택 준비를 진행한다. 실제 도구 슬롯보다 많은 동시 실행을 약속하지 않는다.

## 도구와 권한

- 파일·코드는 검색/읽기·Git diff부터 확인한다.
- Unity는 관련 스킬과 설치된 CLI/MCP에서 프로젝트를 지정한다. 상태 연결과 명령 성공을 구분한다.
- 서버·ClientCore 요청/응답을 직접 추적하고 옛 문서를 현재 계약으로 단정하지 않는다.
- GitHub·Slack 맥락은 연결 도구로 읽고 Slack 발신은 SLACK_WORKFLOW의 앱 도구만 사용한다.
- 실제 입력은 현재 허용·화면을 확인한다. 다른 게임이 앞에 있거나 도구가 중단되면 입력을 멈추고 허용을 확인하며 독립 작업은 계속한다.
- 패키지·외부 도구·비용은 실제 필요와 기존 범위를 확인한다. 권한·보안을 임의 변경하지 않는다.

프로젝트 config는 기본값이며 관리 정책·세션 재정의·도구 권한이 우선할 수 있다. 글로벌 config의 비밀·환경 전체를 출력하지 않는다. trusted/MCP 설정만으로 보호 경로 쓰기·네트워크·실입력 허용을 단정하지 않는다.

과거 P01은 기록이며 새 권한을 부여하지 않는다. 기존 승인 범위의 서버·맵·프로토콜 후보는 구현 가능하되 새 계약·운영·DB 파괴·비밀·비용은 공통 승인 경계를 따른다.

AGENT_USAGE에 실제 생성·재활성화·역할·산출물과 확인 가능한 모델/토큰만 남긴다. 전체·역할 합계를 대조하고 미노출 토큰은 N/A다. 호출 수를 늘리지 않는다.

초기 구축·P01·옛 모델 지침은 [원문 이력](history/2026-10-24-guideline-audit/README.md)에 보존한다.

설정 근거: [공식 Subagents](https://learn.chatgpt.com/docs/agent-configuration/subagents). 프로젝트 설정과 역할 TOML을 검증하며, 문서상 권장·실제 새 배정의 모델·현재 총괄 모델은 별개로 기록한다.

## 사용량 절약 — 2026-10-25
선택지 취합·응답 연결은 Luna/low로 낮추고, 기록은 기존 Luna/low를 유지한다. 실제 기획 판단·아트 제작·구현·리뷰·입력 검증의 기본값은 유지한다. 의사결정 지원 담당이 새 디자인 판단까지 맡아야 하면 해당 부분만 기획/아트 역할에 넘긴다. Coordinator 설정은 사용자 앱 선택을 유지한다. 다음 신규 배정부터 실제 모델을 확인하며 기존 실행에 소급 적용했다고 보고하지 않는다. 등록되지 않은 선택지 역할은 default 역할에 Luna/low와 필요한 맥락만 명시한다.

## 작업 난도별 배정과 하위 Agent

- 범위가 명확한 자료 취합·문구 정리·파일 목록 대조는 Luna/low, 명세가 확정된 독립 수정·결정적인 검사 실행은 Luna/medium을 우선 검토한다. 테스트 역할 기본 Luna/medium과 기록·의사결정 지원 기본 Luna/low는 유지한다.
- 복잡한 구현·상태 수명·네트워크 계약·독립 리뷰·새 기획 판단은 Sol/medium, 아트 제작과 어려운 시각 판단은 기존 Sol/high를 유지한다. 근거 있는 어려운 문제만 해당 작업의 추론을 올린다. Luna에서 재시도와 인계 비용이 커지면 같은 시도를 반복하지 않고 Sol로 좁혀 인계한다.
- 역할의 고정 기본 모델을 호출 인자로 변경할 수 없으면 default/worker 신규 배정에 모델·추론·실제 책임·관련 지침을 명시한다. 역할 집계는 default라는 실행 이름 대신 실제 담당 책임을 기록한다. 기존 실행 모델까지 변경됐다고 주장하지 않는다.
- 하위 Agent도 충분한 독립 작업이 있으면 Luna 하위 작업을 배정할 수 있다. 목표·담당 파일·금지 범위·완료 조건·필요한 맥락만 전달하고, 다른 담당자가 있으며 그 변경을 되돌리지 말라고 명시한다. 시작 전에 Coordinator와 소유권·실제 가용 슬롯을 확인한다. 슬롯은 전체 계층이 공유하며 부모별로 새로 생기지 않는다.
- 한 번의 직접 수정으로 끝날 일, 같은 파일이나 Editor를 동시에 쓰는 일, 기다리기만 하는 일은 재위임하지 않는다. 기본적으로 실행 담당에서 한 단계만 더 분해하고, 더 깊은 배정은 Coordinator와 필요성을 확인한다. 호출을 늘리거나 같은 답을 여러 모델로 생성해 투표하는 방식을 기본 절차로 삼지 않는다.
- 부모 Agent는 결과를 통합하고 필요한 부분만 검토한다. 이미 통과한 검사를 재실행하지 않는다. 전체 이력 복제보다 필요한 코드·계약·결정만 전달하며, 실제 사용 모델·활성화만 지표에 남긴다.
- Coordinator의 사용자 선택 목표는 Sol/medium이다. 앱에서 실제 변경됐는지는 세션 근거가 있을 때만 확인됐다고 기록하며, 이 문서나 프로젝트 설정으로 Coordinator 모델을 덮어쓰지 않는다.
