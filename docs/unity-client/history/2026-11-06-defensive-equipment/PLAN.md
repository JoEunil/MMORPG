## 현재 사실과 피해 근거

- `CoreLib/ItemData.h`: 철방패 ID4·가죽갑옷 ID5는 이름·종류·무게만 있고 방어 효과가 없다. `CharacterState.h`는 철검 ID3 장착·공격 보너스만 제공한다.
- `HuntingZoneData.h`와 `Monsters.inc`의 현재 연결: 일반 공격력50~150×기본공격 계수5 → 250~750, 강한 몬스터80~240×특수 계수15 → 1,200~3,600, 보스18/30×계수100 → 각 타격1,800/3,000. 계수100인 미사용 스킬2를 일반 몬스터 피해로 세지 않는다.
- `MonsterSkills.inc`의 현재 flags 0/2는 치명타 bit0이 꺼져 있다. `ZoneState_Skills.cpp::ApplyHit`는 공격×계수 → 치명타 조건이면×2 → 특수 공격 패링 성공 시 차감 생략 → HP 차감 순서다. 아래 비교는 이 실데이터의 산술 예시이며 체감·실전 성공 증거가 아니다.

- 추천 이유: 현재 공격 피해 폭이 커 비율 합산 A가 낮은 기본 공격과 큰 특수 공격에 같은 방어 비중을 준다. 두 수치 묶음 모두 신규 제안이며 기존 철검+2 승인을 방어 수치 승인으로 확대하지 않는다. 요소 혼합·둘 다 보류도 가능하다.
- 이번 선택에 파츠·재질·모델·리깅 변경을 포함하지 않는다. 가죽갑옷5도 외형을 바꾸지 않는다. 타인 장착 외형 동기화 역시 현 wire에 없어 제외하며, 별도 요구 시 full/delta·ClientCore 계약 추가 부담을 제시한다.
- 기존 거래 경로가 있다는 사실과 실제 방패·갑옷 매물/보유품이 있다는 사실은 다르다. 현재 매물·보유는 미확인이다. 없으면 검증 전제 미충족으로 기록하며 드랍·상점·제작·DB 지급을 새로 만들지 않는다.

## 입력·UI·실패 흐름 제안

- I 가방 → 보유 방패/갑옷 선택 → 상세의 장착/해제 → 서버 확정 응답 후 슬롯·장착 표시·효과 갱신. 기존 철검 표시와 나란히 방패/갑옷 상태 및 선택 정책의 합계만 보여주며 새 단축키는 없다.
- 요청 중 중복 조작을 막고 미보유·잘못된 슬롯·차감 충돌·저장 실패는 기존 장착을 유지하고 실패 이유를 알린다. 클라 클릭만으로 장착/방어 성공을 확정하지 않는다.
- 창 닫기는 확정 장착을 되돌리지 않는다. 통신 단절·구역 전환·늦은 응답은 기존 requestID/epoch 수명을 따르고 재접속 조회로 서버 상태를 복원한다. 철검 공격 보너스와 무장과 무관한 Space 패링/3초 쿨을 유지한다. 방패 장착을 패링 조건으로 만들지 않으며 기존 방패 파츠를 사용하는 패링 표현도 보존한다.

## 계약 영향·착수 경계

- 선택 후 필요한 변경: 서버 아이템 방어 데이터/내보내기, 슬롯 권위·피해 계산·수량 보호, ClientCore 장착 조회/변경·초기 상태, Unity 가방 슬롯·장착 표시·방어 수치. 서버 분석으로 실제 필드·길이·구역 전달·동시 적용 범위를 확정한 뒤 구현한다.
- 저장은 무기·방패·갑옷을 명시하는 새 inventory 버전과 새 WAL 식별을 한 번에 묶고 기존368/type2 및 지원 구형 읽기를 유지한다. 빈 tag/slot/padding 재사용·새 DB 스키마는 제외한다. 새 저장 후 구 서버 직접 복귀 제한과 백업/복구 방안을 선택에 함께 알린다.
- AI·이동·aggro·공격 phase/계수·드랍·상점·제작·포션·경제 변경은 제외한다. 본 정책 선택은 push/게시·실입력·DB 변경 승인으로 해석하지 않는다.

## 구현 후 최소 검증과 완료 조건

1. 서버/fixture: 무장착·각 단독·동시장착의 기본/특수 피해와 최소1·원피해0·기존 치명타 순서·패링0을 한 시나리오로 확인. 예고 시작 후 장착 변경·다단 타격 시점과 비율 범위 오류 거부·넓은 정수 곱/내림도 포함한다.
2. 상태/저장: 기존 철검과 세 슬롯의 보유 검증·수량 보존·동일ID 모든 스택 차감 차단, 구역/재접속/서버 정상 재시작 복원, 지원 구형 읽기·새 WAL 복구·실패 시 기존 상태 보존을 묶어 확인한다.
3. 실입력/화면(현재 입력 허용 확인 후): 실제 보유/정상 거래로 확보한 방패·갑옷을 가방 장착→피격→해제하고 확정 HP 변화·판매 전 해제·가방 슬롯/장착 표시/방어 수치를 확인한다. 기존 기사·방패 파츠·패링 표현 보존도 확인한다. 재화/아이템 변화를 기록하며 미보유는 차단으로 남긴다.

- 완료: 선택 정책과 계약에 맞는 실제 서버 피해·세 슬롯 영속·판매 보호·가방 슬롯/장착 표시/방어 수치 및 기존 외형·패링 보존이 같은 후보에서 확인되고, 위3개 이내 시나리오의 실제 결과·미검증·복구 상태를 기록한다. 검산/fixture 통과를 체감 평가로 보고하지 않는다.
