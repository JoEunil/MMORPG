# 검수 기록

## 계획

새 종합 검수 담당 `web_structure_quality`가 PLAN.md를 검토했다. 필수 수정 없이 계획 통과. 경험 회고에도 축약 기준을 적용하고, 벡터 후보 A도 자동 채택하지 않고 같은 기준으로 검사하라는 보완을 계획에 반영했다.

## 이미지 후보

후보 파일은 ROOT/UnityClient/Builds/ContentTourCapture-2026-11-02/workflow-options에 보존한다. A는 웹에 사용하는 편집 가능한 SVG 이미지, B·C는 built-in imagegen 생성 PNG다. 이전 미채택 초안은 사이트에서 참조하지 않는다.

| 후보 | 구성 | 검수 판정 |
| --- | --- | --- |
| A | 동일 규격 상자, PC 트리·모바일 공통 분기선 | 모바일 수정 후 채택 |
| B | 생성 이미지, 위에서 아래로 배정 트리 | 피드백이 의사결정 지원으로 연결되고 상자 크기가 달라 제외 |
| C | 생성 이미지, 왼쪽에서 오른쪽으로 역할 분담 | 구현·아트에서 검토로 향하는 연결 누락과 상자 크기 차이로 제외 |

공통 제작 요청: 사용자, 총괄 Agent, 서버 분석·기획, 구현·아트, 의사결정 지원, 검토·검증, 기록 Agent의 일곱 상자. 같은 역할·문구로 비교하고 총괄의 책임에 통합을 포함한다. 총괄 통합이라는 별도 역할은 만들지 않는다. 필요한 역할만 병렬 배정하고 검수 피드백은 같은 제작 담당자에게 돌아간다. 흰 배경, 짙은 글자, 얇은 연결선, 장식·입체감 제외.

A의 원 제작 담당인 총괄이 모바일의 문구·선 겹침과 결과 수렴선을 수정했다. 기존 fullPage 캡처는 화면 아래 영역이 하얗게 저장돼 이미지 전체 증거로 사용할 수 없었다. 실제 viewport의 상·하단 연속 캡처로 기록 Agent와 결과 전달 문구까지 확인했다. 같은 검수 담당이 수정본 통과/필수0으로 판정했다.

최종 선택: `site/media/diagrams/agent-workflow-desktop.svg`, `agent-workflow-mobile.svg`. 사이트에는 선택한 A만 적용한다. 이미지 선택 통과와 최종 페이지 검수는 별개다.

## 최종 통합

같은 검수 담당이 계획→이미지 비교→A 모바일 수정본→최종 통합 화면을 검토했다. 최종 통합 검수 통과/필수0이다. 실제 PC·모바일 홈에서 2D 화면 노출(PC 이미지 상단417px, 모바일590px), 명사형 기능 목록·비교표, 활용 기록 안의 선택 시안, 최종 도식을 확인했다.

총괄은 엄격 빌드와 경로·앵커·미디어 검사, 홈→상세 2단계 탐색 검사, 일반 본문 링크0·원본 이미지 링크0을 확인했다. 홈의 다섯 대표 이미지 틀은 PC에서 모두573×322.3125px로 일치했다. PC1265px·모바일375px에서 가로 넘침0이었다. 실제 GIF8개를 보존하고 기본 베기 펼침 후 GIF960px 로드를 확인했다. 실제 모바일 기기나 느린 네트워크 성능을 측정한 것은 아니다.

지표 갱신은 최종 시각 검수와 별도로 확인했다. 새219·후속342·합계561이 공개 요약과 역할별 표 합계에 일치한다. 이미지 생성이나 총괄 직접 작업은 Agent 실행으로 집계하지 않았다. 후보 파일의 실제 토큰·비용은 N/A다.

브라우저 증거는 ROOT/UnityClient/Builds/ContentTourCapture-2026-11-02의 `structure-*.jpg`에 보존한다. 선택된 웹 이미지 원본은 SVG 두 개이며 생성 후보B·C는 내부 비교용으로만 보존한다. 게임·서버 코드나 Unity 입력을 이번 웹 재구성에서 변경·검증하지 않았다. 새 후보의 원격 게시·배포는 별도 승인과 결과 확인이 필요하다.
