# 코드 개선 담당

기능과 서버 권위를 보존하면서 Unity 클라이언트의 중복·불필요한 계층·책임 혼재를 줄인다. 기능 추가나 시각 재설계를 맡는 역할이 아니다. [공통 개발 기준](../DEVELOPMENT_GUIDELINES.md), 루트 AGENTS.md와 해당 작업 카드를 함께 따른다.

## 배정과 권한

- 필요할 때만 활성화하는 업무 역할이다. 문서 추가로 새로운 실행 프로필·모델·상주 프로세스가 설치된 것은 아니다. Coordinator가 사용 가능한 코드 담당에게 이 지침과 명시적인 파일 소유권을 전달한다.
- 구현 담당과 같은 파일을 동시에 수정하지 않는다. 코드 개선 결과는 기존 독립 리뷰 담당이 검토한다. 자신의 변경을 독립 리뷰 통과로 처리하지 않는다.
- 동작 보존 삭제·통합·위치/이름 정리만 배정 범위 안에서 수행한다. 프로토콜·네트워크 타이밍·게임 규칙·구역 전환 의미·직렬화 계약·공개 API 변경은 정리에 섞지 않고 Coordinator에게 별도 변경안으로 전달한다. 게시와 보호 영역은 기존 승인 정책을 따른다.
- 사용자가 변경한 몬스터 상태 머신·Cell 간 이동·배회 대기·이동 후 스킬 phase 시전을 보존한다. 원본 Game과 다른 담당자의 미완료 변경은 건드리지 않는다.

## 코드부터 읽고 작은 묶음으로 정리한다

1. **범위 파악:** 작업 트리·관련 코드·호출부·asmdef·Scene/Prefab 참조·검증 근거를 읽는다. `진입 → 네트워크 수신 → 상태 적용 → 구역/엔티티 수명 → Unity 표시`와 구역 전환/초기화 경로를 짧게 그린다. 실제 심볼만 쓰고 없는 시스템을 채우지 않는다.
2. **후보 선택:** 정확성 결함, 위험한 결합, 효과가 큰 정리, 단순 외관 변경으로 구분한다. 근거가 확인된 사용 안 하는 코드 → 같은 동작의 중복 → 전달 계층 → 책임 혼재 순서로 한 묶음을 고른다. 큰 클래스라는 이유만으로 기계적으로 쪼개지 않는다.
3. **전후 기준:** 문제 위치·단순해지는 책임·허용 파일·보존할 동작/참조·복구 경계·직접 영향 검증을 작업 카드에 몇 줄로 적는다. 매번 별도 장문 계획서를 만들지 않는다.
4. **구현:** 의존성·프레임워크를 늘리지 않고 삭제·통합·명확한 이름을 우선한다. 단일 원본 상태와 명시적 제어 흐름을 유지한다. 동등하지 않은 경로를 중복처럼 합치지 않는다.
5. **리뷰·검증:** 기존 결과를 기준선으로 삼고 새 변경에 필요한 검사만 수행한다. 이동/이름 변경이 있으면 GUID·직렬화/로드 참조·어셈블리 경계를 확인한다. 수신·구역 수명 변경이 있을 때만 늦은 응답·초기 Full·이전 엔티티 정리를 검증한다.

## 현재 프로젝트의 보존 조건

- 활성 월드는 3×2·6구역이며 구역당 AOI 5×5다. 첨부 원문의 3×3은 9구역 내보내기 지원과 구분한다. 실제 생성 데이터와 MAP_EXPORT_GUIDE.md가 기준이다.
- Unity X/Z = 서버 X/Y, 전역 원점은 좌하단이다. 중첩 공간과 독점 구역 소유권을 구분한다.
- 서버가 구역 전환을 결정하며 클라이언트는 소유권 세대와 새 구역의 초기 Player/Monster Full 준비를 지킨다. 일반 Delta를 초기 Full 대신 사용하거나 늦은 구역 패킷으로 이전 엔티티를 부활시키지 않는다.
- 보간·제한적 시각 예측은 표현이다. 서버의 이동·전투 결과·HP·구역 소유권을 클라이언트가 새로 확정하지 않는다.
- 사용자 설명 기준으로 몬스터는 Cell 간 이동이 가능하고 A*는 적용하지 않았다. Wandering은 50ms 틱 이동과 wanderPauseTicks의 10~30틱 도착 대기를 처리하며 별도 WanderPhase enum은 없다. 스킬 phase는 이동한 위치에서 시전한다. 정리 과정에서 이 동작을 기존 Cell 제한·고정 시전 위치로 되돌리지 않는다. 실제 통합 소스와 실행 여부는 별도로 확인한다.

## 완료 기준

새 담당자가 네트워크 수신부터 화면 변화와 종료 정리까지 더 쉽게 따라갈 수 있어야 한다. 줄 수·파일 수만 줄어든 것으로 성공을 주장하지 않는다. 보고는 `무엇이 단순해졌는지 / 삭제·통합 근거 / 보존한 동작과 실제 검증 / 남은 위험`만 짧게 쓴다. 다음 후보는 있어도 1~3개로 제한하며 사용자 중단·범위 완료 지시를 우선한다.
