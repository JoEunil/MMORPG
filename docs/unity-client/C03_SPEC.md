# C03 — 기존 Zone 클릭 이동 명세

상태: Coordinator가 서버 변경 없는 클라이언트 최소안을 수용했다. wire 및 실행 경로는 [C03_CONTRACT.md](C03_CONTRACT.md)를 기준으로 한다. Unity 입력 테스트는 사용자 지시로 보류 중이며 배치에만 후보를 기록한다.

## 목표와 경계

C02의 실제 로그인·캐릭터 선택·Zone 진입 뒤, 현재 Zone 안에서 지면 클릭을 따라 본인 캐릭터를 이동시킨다. 기존 ACTION 패킷과 서버 위치 판정을 사용한다. ACTION 좌표는 클릭 목적지/속도 명령이 아니라 절대 위치 요청이다. 서버 확정 위치는 실제 수신한 Full/Delta 순서대로 반영한다. 이동 ACK·서버 snapshot 순번이 없으므로 입력별 확정이나 broadcast 생성 순서 복원으로 표현하지 않는다.

포함: 월드 지면 클릭, 이동 전용 ACTION 송신, 본인 위치·방향의 서버 확정 표시, 클릭 목적지의 최소 상태, 포커스·화면·연결 수명에 따른 입력 차단과 정리.

제외: UI 클릭 이동, 채팅/텍스트 입력 중 이동, 공격·스킬·몬스터·타 플레이어 기능, 새 충돌/경로탐색 판정, Zone 전환, 목적지 순간이동, 미지원 버튼·더미 UI.

## 고정 구현 기준

- 이동 전용 ACTION은 `skillSlot=255 (NONE_SKILL)`이어야 한다. 기존 wire 본문은 `dir u8, x f32, y f32, skillSlot u8`이고 x/y는 절대 위치다. 최초 ClientTick과의 경쟁으로 skillSlot 0이 나가지 않도록 최초 상태도 255로 초기화하는 것은 계약의 선행 조건이다.
- 요청 후보는 최신 본인 서버 확정 좌표에서 목표 방향으로 최대 1 Unity 단위다. 명목 50ms보다 자주 보내지 않는다. 목표까지의 장거리 좌표를 한 번에 보내지 않으며 지연된 프레임에서 dt 기반 다중 catch-up/거리 도약을 만들지 않는다. 실제 속도와 도달은 서버 이동 예산 및 수신 갱신에 따른다.
- 이동 방향은 이동용 기준 `0=+Y`, `1=-Y`, `2=-X`, `3=+X`로 둔다. 대각선 목표는 더 큰 축으로 정하고 동률이면 X축을 택한다. 이는 이동 facing만 뜻하며 전투 스킬 방향에 적용하지 않는다.
- Zone1의 현재 계약 범위는 x/y 각각 `[-5,105]`이며 포함 경계다. 입력 목적지는 현재 Zone 실제 범위 안으로 제한하고 다른 Zone으로 넘어가는 요청이나 자동 ZoneChange를 보내지 않는다. 장식 지형을 충돌 불가 판정으로 취급하지 않는다.
- Transform은 최신 서버 확정 좌표를 보존한다. 위치 보간은 필수가 아니다. 추가한다면 별도 시각 표현에만 적용하고, 서버 확정 좌표/시각 위치/클릭 목표를 혼동시키지 않는다.
- 수신 순서대로 서버 확정 Full/Delta를 반영한다. ACK, sequence, snapshot tick이 없으므로 수신한 늦은 packet의 생성시점 순서를 추정하거나 입력별 성공을 단정하지 않는다.
- 클릭 교체·도착·타임아웃·disable·새 Client/Zone·연결 해제 시 남은 목표/예약 송신을 정리한다. 이미 ClientTick/TCP에 넘긴 ACTION segment는 소급 취소할 수 없다. 따라서 정리는 이후 목표/잔여 후보를 중단하는 뜻이며 이미 전달한 요청의 취소나 롤백을 보장하지 않는다.
- 유효한 C02 Zone 및 일치 본인 Full 전, 실패 상태, 연결 종료 상태에서는 새 이동 요청을 만들지 않는다. UI 위 클릭과 UI 입력 포커스 상태는 월드 이동으로 해석하지 않는다. 지면 밖/유효하지 않은 점, NaN/Infinity, 계약 범위를 벗어난 위치는 보내기 전에 거부한다.

## 사용자 흐름

1. C02가 현재 Zone과 동일한 본인 Full을 확인한 뒤 월드 입력을 활성화한다. 로그인/목록 화면, 진입 대기·실패, 종료/연결 해제 중에는 이동을 요청하지 않는다.
2. 이동 가능한 바닥을 클릭하면 입력을 현재 Zone 범위로 검사하고 목적지를 보관한다. 후보는 최신 서버 확정 좌표에서 최대 1단위이며 간격은 50ms 이상이다. 이동 요청은 NONE_SKILL로 보낸다.
3. 화면상 확정 Transform은 서버에서 수신한 위치·방향으로 갱신한다. 클릭 즉시 목적지에 이동시키지 않는다. 보간을 넣을 경우에도 서버 확정 Transform/좌표를 보존한다.
4. 새 클릭은 남은 목적지 계획을 교체한다. 목표 도착, 유한 timeout, 입력/화면 비활성, Zone 상태 무효화 및 연결 종료 때 남은 목적지와 송신 대기를 정리한다. 이미 ClientTick/TCP에 전달된 최대 한 segment는 취소됐다고 주장하지 않는다.
5. 이동 결과는 서버 확정 좌표 갱신으로만 판단한다. ACTION ACK나 broadcast 생성 순서는 없으므로 입력별 승인/거부를 임의로 표시하지 않는다. 본인 확정 좌표가 일정 시간 갱신되지 않으면 유한 timeout으로 추가 송신을 중지한다.

## 수용 조건

1. C02의 유효한 현재 Zone 및 동일 ID 본인 Full 전·진입 실패 후·연결 종료 후에는 클릭으로 ACTION이 생성되지 않고 이전 목적지/예약 송신도 새 연결에 남지 않는다.
2. 월드 지면 클릭은 확정 계약의 ACTION 형식, `skillSlot=255`, 현재 Zone 유효 범위, 최신 서버 좌표 기준 최대 1단위 후보로만 처리된다. UI 클릭/포커스, 유효하지 않은 점, NaN/Infinity는 요청을 만들지 않는다.
3. ACTION 송신 간격은 최소 50ms이며 긴 프레임에서 밀린 횟수만큼 catch-up 송신하지 않는다. 목적지까지 순간이동하거나 큰 단일 좌표 도약을 보내지 않는다.
4. 캐릭터의 확정 Transform/위치/방향은 실제 수신한 본인 Full/Delta를 수신 순서대로 반영한다. ACK나 snapshot 순번이 없는 한 입력별 성공, broadcast 원래 생성 순서, 미수신 상태의 확정을 주장하지 않는다. 화면 보간은 선택 사항이며 서버 확정 좌표를 보존한다.
5. 목표 교체·도착·유한 timeout·화면/컴포넌트 비활성·Zone 무효화·연결 종료 시 잔여 목적지 송신을 정리한다. 이미 ClientTick/TCP에 전달한 segment는 취소/롤백됐다고 간주하지 않으며 별도 서버 패킷 취소를 추가하지 않는다.

## 입력 테스트 배치 후보 — 실행 보류

아래를 INPUT_TEST_BATCH.md에 등록할 후보로 둔다. 사용자 재개와 최종 제품 동결 전에 Unity Play/입력/실행 캡처를 하지 않는다. C03의 실제 값·보호 조건은 C03_CONTRACT.md 및 구현된 검토 버전에 맞춰 Coordinator가 배치 갱신 시 고정한다.

- C02 로그인→목록→본인 선택→Zone/Full 진입 뒤 가까운 월드 지면을 클릭: 이동 요청 필드/255 sentinel/후보 ≤1 확인, 서버 본인 Full/Delta로 좌표 전진 관찰.
- 먼 지점 및 대각선 동률 클릭: 간격 ≥50ms, catch-up/장거리 도약 없음, 이동 방향 규칙 확인.
- UI 버튼/목록/패널 클릭과 입력 포커스 상태: ACTION 추가 송신 없음.
- 서버 위치 갱신 전 클릭 지점으로 이동하지 않음, 갱신 후 서버 확정 Transform 일치 확인. 보간이 있으면 시각 위치와 서버 좌표를 구분.
- 목적지 교체, 무갱신 timeout, 컴포넌트/화면 비활성 및 연결 해제: 잔여 목표가 중지되고 재접속 후 자동 송신 없음. 이미 전달한 segment 취소를 검증 조건으로 잘못 요구하지 않음.
- Zone 경계는 현재 Zone 범위 제한을 확인하고 Zone 전환 없음 확인.

테스트 작성/실행은 사용자 재개 전까지 보류한다. 배치 실행 시 공통 로그인/선택/진입 흐름에 C02-AUTH 회귀를 합치고, 새 입력 조건만 추가한다. 예상 비용·종료 조건은 구현과 검토 helper를 고정한 뒤 입력 배치 카드에서 결정한다.
