# 정통 판타지 MMORPG 개편 계획

2026-10-20 사용자 요청을 반영한 현재 기준. 이번 변경은 계획·운영 기록이며 게임 구현이나 모델 설정 전환을 완료한 것이 아니다. 이전 카툰/스타일라이즈드 방향과 클릭 이동 우선 정책보다 아래 기준을 우선한다. 기존 완료 기능과 미게시 거래소·콘텐츠 후보는 보존한다.

## 목표와 범위

- 시각 방향은 리니지1 계열에서 느껴지는 정통 판타지 MMORPG로 잡는다. 기존 3D 쿼터뷰 기반에서 성인 캐릭터 비례, 갑옷·무기 세부 형태, 자연스러운 재질·지면·식생, 절제된 장식 UI를 사용한다. 전체 화면을 어둡게 하는 것 자체를 목표로 삼지 않는다. 정확한 시리즈별 세부 취향은 대표 화면 확인에서 조정한다.
- 방향키 지속 입력으로 이동하고 키를 놓으면 정지한다. UI/채팅 입력 중 이동·스킬을 막고 동시 방향 입력의 속도 증가를 방지한다. 서버 이동 예산·좌표·4방향 시전 계약과 일치시킨다. 마우스는 UI·대상 선택에 사용하며 지면 클릭 이동은 기본 조작에서 제외한다.
- 현 서버의 스킬 슬롯 3개는 Z/X/C로 변경한다. V는 요구 키 영역으로 기록하지만 실제 연결할 기존 행동을 정하기 전에는 비워 둔다. 네 번째 스킬이나 가짜 슬롯을 추가하지 않는다.
- 텍스트 나열형 표시를 HP/MP/경험치 바, 스킬 아이콘·쿨다운, 인벤토리 슬롯, 거래소 목록·선택·가격·확인 UI로 바꾼다. 이름·수량·가격·도움말 등 필요한 글은 유지한다. 서버 확정 상태만 표현하고 미지원 기능을 활성화하지 않는다.
- 레벨 디자인은 기존 레벨·경험치·캐릭터/몬스터 수치·스킬·아이템 계약을 기준으로 초반 사냥의 이동 시간, 적 밀도, 처치 시간, 위험 구간, 보상과 성장 체감을 맞추는 작업으로 정의한다. 새 직업·장착·소비·드롭 규칙은 현 서버 지원을 확인한 뒤 필요한 범위를 따로 정한다.
- 플레이어/몬스터 이동·공격 간격과 추적/어그로 해제/복귀 등 현재 AI를 서버 기준으로 조정한다. 화면 애니메이션만 느리게 만들어 속도 불일치를 숨기지 않는다. 실제 이동 가능 영역과 맞는 맵부터 만들며 서버에 없는 충돌·경로 탐색이 완성된 것처럼 장벽을 배치하지 않는다.

## 토큰과 재작업을 줄이는 순서

| 순서 | 작업 묶음 | 완료 기준 |
| --- | --- | --- |
| 1 | 방향 기준과 변경 표 | 레퍼런스·캐릭터 비례·UI 밀도·재사용/교체 자산을 짧게 정하고 기존 입력/속도/AI 계약을 한 번 조사한다. |
| 2 | 조작·전투 템포 | 기존 임시 외형으로 방향키·ZXC와 이동/추적/공격 속도를 맞춘다. 기준 수치와 맵 동선 블록아웃을 정해 이후 아트 재작업을 줄인다. |
| 3 | 대표 사냥 화면 | 플레이어 1종·몬스터 1종·필드 한 구간과 HP/MP·스킬 HUD를 실제 쿼터뷰 카메라에서 함께 완성한다. 공통 UI 스타일/아이콘/재질을 이 화면에서 확인한 뒤 확장한다. |
| 4 | 사냥터와 성장 구성 | 승인된 대표 화면을 재사용해 한 사냥터의 동선·적 배치·난이도·기존 보상/성장 수치를 맞추고 다른 기존 몬스터·스킬·아이템 표현을 넓힌다. |
| 5 | 나머지 UI와 거래소 | 로그인·캐릭터 선택·인벤토리·채팅·거래소의 텍스트 나열을 공통 UI로 교체한다. 기존 구매/취소/수령 후보를 재사용하고 등록의 영속성 문제는 외형 작업과 분리해 해결한다. |
| 6 | 묶음 검증·전달 | 관련 구현을 동결·독립 리뷰한 뒤 직접 영향 자동 2~3개와 실제 조작 1회로 확인하고 실제 화면/사이트 기록을 갱신한다. 기능 묶음 단위 큰 PR로 전달한다. |

대표 화면의 에디터 시각 확인은 가능하지만 저작 중 기능마다 Play/로그인을 반복하지 않는다. 단계 2~3은 한 플레이 경험 묶음으로 검증할 수 있다. 최종 수치·맵 구조에 영향 없는 이미지/배치 수정은 해당 화면만 확인한다. 디자인 방향 확인 전 캐릭터·필드·패널을 대량 제작하지 않는다.

## 모델·역할 사용

- 대표 화면 구성과 품질 판단처럼 어려운 결정에 상위 모델을 짧게 배정하는 방식을 권장한다. Astra는 후보이며 실제 실행 도구/역할 설정에서 선택됐는지 확인한 뒤에만 사용했다고 기록한다.
- 일반 구현·통합·검토는 Sol 계열, 확정 규격의 반복 임포트·표 정리 등은 가벼운 모델을 사용한다. 모델 이름만 바꾸고 이미지·리깅·애니메이션 품질이 자동 개선됐다고 주장하지 않는다.
- 좋은 원본 에셋·재질·애니메이션·이미지 생성 도구와 실제 게임 카메라 비교가 필요하다. 구매/새 유료 도구는 예산 확인 뒤 진행한다. 원본 리소스와 출처를 기록한다.
- 전체 대화 복제 대신 짧은 작업 카드와 기준 화면/허용 파일/수용 조건만 전달한다. 같은 담당을 재사용하고 같은 파일·Editor 동시 조작은 금지한다.
- 에이전트 활용 지표는 [AGENT_USAGE.md](AGENT_USAGE.md)를 따른다. 보고용으로 불필요한 에이전트를 호출하지 않는다.

## 진행률 해석

기존 로그인·필드·전투 연결의 완료 사실은 유지한다. 그러나 이 개편은 입력·AI·아트·UI·밸런스의 새 작업 범위이므로 이전 70~80% 추정치를 그대로 개편 완료율로 쓰지 않는다. 새 묶음은 구현 전이며 각 묶음의 검증된 완료 여부로 진행을 보여준다. PR 게시 전 Slack 승인 및 자동 브랜치 삭제/로컬 안전 정리 규칙은 유지한다.
