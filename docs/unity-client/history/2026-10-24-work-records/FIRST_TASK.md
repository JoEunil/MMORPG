# C01 — 로그인 후 캐릭터 목록 표시

상태: 완료 / Coordinator 수용. 2026-10-18 이 채팅의 사용자 시작 지시를 근거로 착수했다. ClientCore/Unity 컴파일·독립 리뷰·프로토콜/목록 fixture 3개를 통과했다. NUnit UI runner의 문자 입력 실패는 기록을 유지하며, 같은 UI 코루틴과 assertion을 Editor-update 도우미로 실행해 실제 실패/재시도·TCP 인증/목록 응답·Scene 재로딩 및 실제 Play 종료/재시작 검증을 통과했다. 제품·Scene·DLL의 식별값은 유지했다. PNG와 6초 정적 결과 GIF를 생성해 직접 시각 검증했다. 실행 요약은 UnityClient/Captures/c01-test.txt, 진행 상태는 PROGRESS.md를 따른다.

## 목표와 범위

Unity의 실제 로그인 입력으로 지정 계정의 서버 캐릭터 목록을 표시한다. 목록이 비어 있으면 빈 상태를 표시한다. 첫 묶음에서 캐릭터 생성·월드 진입·이동·전투·아트·데이터화·거래소는 제외한다.

- 기준: BRIEF.md의 로그인/캐릭터 목록, ClientCore 원본 네트워크·ViewModel·ViewData·dispatcher 경계. 기준 HEAD는 `1d5a3d69074a1de6bafde30f1ec4dfe5cac1a951`, 브랜치는 `codex/unity-ai-client`다. 기존 미커밋 준비 산출물은 별도 보존한다.
- 착수 순서: 실행 환경 복구 확인 → 해당 로그인/인증/목록 계약의 실행 경로 조사 → 허용 파일 확정 → 구현 → 고정 diff 독립 리뷰·실행 검증 → 결과 기록. 계약 불명확 상태로 구현을 배정하지 않는다.
- 계약 조사: HTTP 로그인 응답에서 게임 인증·캐릭터 목록 요청/응답까지 실제 경로와 필드 폭·순서·프레임 길이·종료 경로를 확인한다. 서버 프로토콜 의미는 변경하지 않는다.
- 수정 후보: UnityClient/Assets의 C01 로그인 화면·연결 코드·대상 테스트와 `.meta`, ClientCore의 조사로 특정한 최소 Unity 호환 파일, UnityClient 내 DLL 산출물. 정확한 파일 목록은 조사 후 배정 전에 이 카드에 확정한다. 원본 소스 사본과 DLL을 중복 포함하지 않는다.
- 보호 경계: 서버·DB·인증 정책·프로토콜은 읽기 전용. 원본 ClientCore는 개발 시작 후 허용된 최소 Unity 호환 수정만 적용한다. 포괄 파서/프로토콜 수정은 이 카드로 허용하지 않는다.
- 역할 실행: 계약 분석→최초 네트워크 연결 구현(Sol/high)→독립 리뷰(Sol/medium 고정 역할)·테스트 준비/실행(Luna/medium)→반복 입력 실패 분석·실행(Sol/high)→진행 기록을 배정했다. 전문 역할 동시 실행은 최대 2개를 지켰으며 현재 모두 종료했다.
- Editor 조작권: 최종 테스트 담당이 반납했다. Play/Recorder/도우미 종료 및 임시 입력 장치·runInBackground 원복을 확인했다. 검증 중 제품 쓰기를 중단했고 수정한 테스트 도우미만 좁게 재리뷰했다.

## 완료 조건과 필요한 검증

### 계약 조사 후 확정 범위

- 서버 변경 없음. `SERVER_CONTRACT.md`의 기존 HTTP·TCP 로그인/목록 계약을 유지한다.
- 원본 ClientCore 허용 파일: `ViewModel.cs`, `Interfaces.cs`, `Initializer.cs`, `Network/TCPSocket.cs`, `Services/NetworkService.cs`, `ViewData.cs`, `Services/AuthService.cs`. C01에 필요한 비밀 로그 제거·Unity 종료/재접속 수명·기본 프레임 검증·오류 전달·목록 count 처리만 수정한다. wire 구조와 전투/채팅/프로필 파서는 수정하지 않는다.
- Unity 구현 허용: `Assets/C01/` 런타임 UI/어댑터·해당 asmdef·Editor 생성 도우미·Scene·TMP 기본 리소스(필요시) 및 `.meta`, `Assets/Plugins/ClientCore/`의 빌드 DLL·Json 의존성, `Tools/Build-ClientCore.ps1`. 정확한 생성 파일은 구현 인계 목록에 고정한다. Scene/설정은 Editor API로만 작성한다.
- 테스트 담당 소유: `Assets/Tests/C01/` 테스트·asmdef·테스트용 Editor 도우미 및 `.meta`, `Captures/` txt·PNG·GIF. 제품 구현 담당은 해당 테스트 파일을 수정하지 않는다.
- UI: 기존 런타임 UI 없음, uGUI/TMP 기본안. 서버 결과를 영어로 명확하게 표시하며 신규 게임 기능은 추가하지 않는다.
- 서버의 빈 목록은 `status=0,count=0`으로 실패를 뜻한다. 이를 성공으로 바꾸지 않고 "No characters or list request failed"와 응답 상태를 표시한다. C01 정상 경로의 합격은 실제 HTTP 로그인·TCP 인증 뒤 받은 목록 응답과 화면의 일치다. 비어 있는 계정에 캐릭터를 임의 생성하지 않는다. 비어 있지 않은 목록 표시의 실서버 검증은 계정 데이터가 없으면 미실행으로 구분한다.
- 최초 구현은 네트워크 수명/보안 경계 때문에 PIPELINE_GUIDE·implementer 지침의 예외인 gpt-6.1-sol/high를 사용한다. UI만의 후속 반복 작업은 기본 Luna/medium이다.

1. 실제 UI 입력으로 unity_ai_01 로그인 → 게임 서버 인증 → 해당 계정 캐릭터 목록 수신·표시를 확인한다. 빈 목록도 서버 응답과 일치해야 한다.
2. 잘못된 로그인 입력의 실패를 표시하고 정상 입력으로 재시도할 수 있다. 제품 핸들러 직접 호출을 UI 검증으로 대신하지 않는다.
3. Play 종료·재시작 후 연결/이벤트가 중복되지 않고 정상 로그인할 수 있다. Unity 객체 변경은 메인 스레드에서 한다.
4. 비밀번호·토큰이 로그·캡처에 노출되지 않는다. 같은 고정 변경에 대한 코드 리뷰와 실제 실행 근거, 화면 PNG 및 짧은 대표 GIF를 남긴다. 기능과 캡처 결과는 따로 기록한다.

- 환경: Unity 6000.0.47f1, 지정 로컬 서버, 기존 전용 계정. DB 초기화·기존 계정 변경·임의 캐릭터 생성은 하지 않는다. API 로그인만 완료한 과거 기록을 이번 UI 통과로 사용하지 않는다.
- 검증 비용: 대상 컴파일 1회와 해당 UI 정상/실패 후 재시도/Play 재시작 시나리오 각 1회가 기본이다. 파싱을 수정하면 해당 입력 경계의 회귀만 추가한다. 첫 실행 검증은 20분을 상한으로 하여 미완료·환경 실패를 구분해 보고한다.
- 종료: 필요한 조건을 통과하면 추가 회귀를 넓히지 않는다. 새 변경·실패·미해결 위험이 있을 때 영향 범위만 재검증한다. 동일 원인 수정 2회 후에는 근거와 시도를 Coordinator에 인계한다.
- 산출물: 변경 파일 목록, 실제 소스/DLL 기준, txt 실행 요약, 비밀 없는 PNG/GIF. 관련 검증 후 해당 작업만 커밋 가능하며 push·병합·공개는 별도 승인이다.
