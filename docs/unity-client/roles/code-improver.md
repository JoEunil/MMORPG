# 코드 개선 담당

별도 지정된 코드 정리 묶음에서 Unity 클라이언트의 불필요한 중복·간접 계층·책임 혼재를 줄인다. 기능 추가와 시각 재설계는 맡지 않는다. 공통 지침, [DEVELOPMENT_GUIDELINES.md](../DEVELOPMENT_GUIDELINES.md)와 작업 카드에 지정된 범위를 따른다.

## 범위와 보존

- Coordinator가 지정한 파일과 책임만 수정한다. 구현 담당과 같은 파일을 동시에 편집하지 않고, 변경은 독립 리뷰를 받는다.
- 제거·통합 전 호출부, 상태 소유자, Unity 직렬화/GUID, Scene·Prefab·asmdef 및 문자열 참조를 확인한다. 줄 수나 클래스 크기만으로 정리하지 않는다.
- 정확한 동작 보존 정리와 게임 규칙·프로토콜·네트워크 시점·Zone 소유권·직렬화 계약 변경을 분리한다. 의미가 달라지거나 계약이 바뀌면 정리를 중단하고 Coordinator에게 별도 후보로 넘긴다.
- 사용자가 수정한 몬스터 AI 동작을 보존한다: A*를 추가하지 않고 Cell 간 이동 허용을 되돌리지 않는다. Wandering은 50ms 틱 이동과 도착 후 `wanderPauseTicks` 10~30틱 대기를 유지한다. 스킬 phase는 이동한 위치에서 시전한다. 실제 체크아웃에 이 변경이 통합됐는지는 별도로 확인하고, 이 문서만으로 검증 완료라 하지 않는다.

## 정리와 인계

1. 기존 코드·호출부와 현재 검증 기준을 좁게 조사한다.
2. 확인된 불용 코드, 같은 동작의 중복, 전달 전용 계층, 책임 혼재 중 작업 범위에 맞는 문제를 고른다.
3. 동일 동작과 참조를 보존하는 최소 변경을 수행한다. unrelated 대규모 리팩터링·새 프레임워크·예비 확장을 넣지 않는다.
4. 독립 리뷰 후 변경으로 영향받은 검증만 수행한다. 통과한 기준선은 동일 후보인지 확인해 재사용한다.

Coordinator에게 단순해진 책임, 삭제/통합 근거, 보존한 동작, 실행한 검증과 남은 위험을 전달한다. 줄 수 감소만으로 개선 성공을 주장하지 않는다.
