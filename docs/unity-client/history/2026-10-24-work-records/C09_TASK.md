# C09 — 기존 거래소의 읽기 전용 조회

목표: 인증된 필드 캐릭터가 실제 판매 중 목록을 유형1~3·페이지로 조회하고 반환된 ID·수량·가격·판매자 캐릭터 ID·등록 시각을 표시한다. DB 오류와 정상 빈 결과를 구분한다.

기준: C09_CONTRACT.md, C08 로컬 검증 HEAD df172f6. C08 GitHub 반영 승인은 별도 대기이며 이 지시를 push 승인으로 확대하지 않는다.

포함: TCP26/27 Search 연결, 내부 requestID 왕복, Core/Cache2048 메시지 용량과 sizeof 검사, 정확한 필드 세션 검증, 비동기 응답 수명, 기존 스타일의 조회 UI. 사용자 추가 P2 요청에 따라 로비의 선택 캐릭터 ID를 write-once로 보호하고 늦은 ENTER 응답 회귀를 함께 검증한다. C08의 원자적 전환 경계는 보존한다.

제외: 등록/매매/취소/수령/Outbox/MyList, DB 직접 쓰기·seed·초기화, TEST_BAZAAR 실행, 재화·소유권 규칙 변경, 운영 배포·병합·공개. 정상 테스트 계정 로그인·퇴장 저장은 허용된 환경에서만 발생한다.

소유: c09_server는 CoreLib/CacheLib/NetLibrary의 조회 계약·P2 및 C++ fixture, c09_ui는 새C09화면/setup/UI fixture와 C05 모달 입력 경계. root는 ClientCore/기존 fixture 호환·C02 공개 StopActions 경계·통합·Editor 단독 조작. 정확 파일은 배정 메시지의 소유 범위를 따른다. 타인 정책/미완료 변경은 보존한다.

완료 조건: 실제 SELECT 성공 빈 목록/DB 실패 분리,0~30행 정확한 wire와풀복사, 비인증/잘못된요청 거부, requestID불일치·닫기·전환·timeout·재접속후늦은응답 무반영, 검색중중복요청 차단, 조회UI 입력이이동/스킬로누출되지않음. P2는선택된characterID가다른늦은응답으로변경되지않음과전환/종료경합안전성으로판정한다.

검증: 작업 묶음 구현·독립 리뷰 후 C++ 대상 회귀와 Unity 영향 회귀를 각 한 공통 배치로 실행하고, 실제 로그인→필드→검색/유형/페이지/새로고침/닫기→정상퇴장·캡처를 실행한다. 실DB양수행이없으면 fixture30행과실서버빈성공을구분하고 seed하지않는다. DB검사는전용환경SELECT만한다. 저작중기능/Play시험금지, 테스트중Assets/Packages/ProjectSettings쓰기금지. 예상비용 빌드수분/회귀수초/실입력수분. 통과후새변경·실패근거없으면종료,실패수정은영향범위만재시험.

복구: C09 서버를 별도 final/bin에 빌드하고 C08 서버/DLL 쌍을 보존한다. 무접속 정상 종료·로그/WAL/DB읽기보존 후 후보 기동, 실패시 정상종료 확인후 기존쌍으로복구한다. 기존IOCP종료경고 guard를약화하거나강제종료하지않는다. PR직전만구체diff·리뷰·배치결과·위험·복구안을Slack최종승인요청한다.
